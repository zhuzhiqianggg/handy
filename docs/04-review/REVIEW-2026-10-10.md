# Handy · 顺手 — 项目全面复评（基线 V101 · 2026-10-10）

> **这份文档回答一个问题：为什么我们已经修了 60 多个版本，还在修同一个模块？**
> 它不做版本流水账（那是 `PROJECT_STATUS.md` 的职责），只做**根因诊断 + 债务清单 + 优化方案**。
> 结论先行：**问题不是"改得不够仔细"，而是"架构路线本身在持续生产 bug"**。继续在现有路线上打补丁，
> 第 62 次、第 70 次修复仍会到来。要停表，只能换路线。

---

## 0. 一句话结论

桌面整理模块从 **V30 起选择了「隐藏系统桌面图标、自己接管桌面呈现」** 这条路线。
这条路线要求我们**复刻 Explorer 的整套桌面行为**（Z 序驻留、Win+D 存活、原生右键、新建/改名、
图标尺寸、桌面刷新、回收站交互……），而这些在 Windows 上**没有任何公开接口**。
于是每一个被用户发现的缺口，都变成一轮新的「补丁 + 补丁的补丁 + 保险丝 + 保险丝的保险丝」。

**产品口径的修正**：开源同类（LucidDesk / DeskBox / openFences / DesktopIconMover）**无一接管桌面**，
腾讯桌面整理也不接管。**「不接管原生桌面」不是能力降级，而是回归这类产品的标准形态。**

## 2. 根因诊断：为什么修不完

### 根因 A（决定性）— 路线本身在持续生产 bug

「接管桌面」意味着我们要在自己实现的一套东西里，逐项模仿 Explorer：

| 我们要模仿的原生行为 | 实际代价 | 对应事故 |
| --- | --- | --- |
| 桌面图标层级（永远在窗口之下、桌面之上） | Z 序锚定 + 有界下探自检 + 重排保险丝 + 30s 宽限 + 驻留自愈 | V34 V36 V38 V39 V40 V47 V79 |
| Win+D / 最小化全部窗口 存活 | `IsIconic` 轮询 + `SW_SHOWNOACTIVATE` 还原 | V35 |
| 桌面空白右键菜单 | 代理→双菜单→穿透→自绘，**七轮** | V87–V100 |
| 「新建」+ 就地改名 | ShellNew 枚举 + `LVM_GETEDITCONTROL` 判据 + 安静期 + 有限升级取消 | V88 V92 V93 V94 V95 |
| 图标尺寸/间距/Overlay 叠层 | 读注册表 + 系统图像列表 | V37 |
| 桌面内容变更通知 | 目录签名轮询（因为原生新建不通知我们） | V92 |

**每一行都是一次「我们在扮演操作系统」的赌注，每一次赌错都要用户装一次机来发现。**
V101 刚刚修的「便签减少后格子乱排」，正是这片耦合区里一个纯函数平局裁决写反 —— 症状是桌面级的，
排查却要跨 Rust 布局算法 + 真实库 + 日志 + Python 移植复现。

### 根因 B — 巨型文件让「改 A 坏 B」成为必然

`grid.rs` 同时装着：DB 访问、布局算法（列数裁决/带下拆分/落位）、Win32 桌面接管、Z 序自检、
自愈保险丝、Shell 菜单、图标、拖拽、IPC 命令。**任何两件事共享一个文件和一个全局状态空间**：

- V61 的教训已经写进记忆：「一个跨线程状态只许一个记账人」—— 这正是耦合的症状。
- V79：「显隐唯一真源 `overlay_visible`，谁写谁广播」—— 同上。
- 前端同理：`GridOverlay.tsx` 30 个 `useEffect` 互相通过 ref 传状态，V93 不得不引入
  「改名/新建安静期」来压制 effect 之间的竞速。

**不是我们不够细心，是文件边界没有把「会互相影响的东西」隔开。**

### 根因 C — 验证回路只有一条：用户装机

agent 会话**无法启动本应用**（记忆：「agent 会话启动不了本 GUI ⇒ 打包 + 装机即止」）。
GUI 行为只能靠用户装一次、看一眼、报一次。这条回路把「发现 → 修复」的成本放大到小时级，
**天然鼓励打补丁而不是重设计**（打补丁一眼能验证，重设计要用户重新验收一大片）。

### 根因 D — 补丁层数已超过「人脑可同时持有」的阈值

`CONVENTIONS.md` 2,388 行 + `MEMORY.md` 反复压缩到 12.5 KB 上限，本身就是信号：
**规则多到必须靠"记忆文件"才不会踩坑，说明这些坑应该由结构消灭，而不是靠备忘录。**
（记忆里 V92/V93 反复强调「V92 那条是错的」—— 这就是补丁层之间的自我否定。）

## 4. 优化方案（四批，可独立执行）

### 批次 A — 【核心】落地 B 方案：不接管原生桌面

> 用户 10-10 已拍板。这是**唯一能停止"修不完"的方案**。

**目标形态**：桌面图标**永远归 Explorer 管**，我们只做「装饰 + 遥控」。

| 步骤 | 内容 | 收益 |
| --- | --- | --- |
| A-1 | **停止隐藏 `SysListView32`**；不再自绘文件/文件夹图标 | 一次性删掉：Z 序自检、Win+D 存活、驻留自愈、内容重绘、图标尺寸探测、目录签名轮询 |
| A-2 | 用 `LVM_SETITEMPOSITION` **遥控原生图标位置**（lParam 直接装坐标，**跨进程无需注入**） | 保留「按格子分组摆放」这个核心卖点；前置动作 = 关掉桌面「自动排列 / 对齐网格」（需程序化关闭 + 退出还原） |
| A-3 | 格子改为 **装饰底板 + 标题栏**，内容区 `pointer-events: none` | 原生图标可见可点、原生右键/新建/改名**全部免费回来** ⇒ 删掉 `shell_menu.rs` 的自绘菜单与经典菜单注入、删掉「安静期」链路 |
| A-4 | 右键、新建、改名**全部交还 Explorer** | 删除 V87–V100 七轮的全部代码（约 1,700 行） |
| A-5 | 便签 / 日历 / 工作台 改为**普通桌面浮窗**（不依附接管） | 简化窗口层级管理 |
| A-6 | 数据模型不变（`grid_boxes` / `grid_items` 仍是"登记"） | 无迁移风险，用户数据零影响 |

**预期效果**：`grid.rs` 约 **11,400 → 3,500 行**；`GridOverlay.tsx` 约 **5,228 → 1,200 行**；
`shell_menu.rs` 1,313 → 0；`desktop_menu.rs` 431 → 0；**净删约 13,000 行**，且删除的全部是
"事故高发区"。**这一步之后，本类 bug 的源头不复存在。**

### 批次 B — 模块拆分（可与 A 合并执行）

- `grid.rs` 拆为：`grid/db.rs`（访问）· `grid/layout.rs`（纯布局算法，**无 Win32**）·
  `grid/desktop.rs`（Win32 交互）· `grid/commands.rs`（IPC 薄层）。
  **纯布局算法与 Win32 彻底隔离** ⇒ 布局能脱离真实桌面单测（已有 `layout_all_boxes_with` 注入先例）。
- `GridOverlay.tsx` 拆为：`GridCanvas` / `BoxCard` / `LooseStrip` / `useGridSync` / `useBgMenu`。

### 批次 C — 工程债清理（低风险，随时可做）

- 删 `desktop_handoff.rs` 死重、`itemDragging` 死状态、`ensure_dir` 死代码、3 个休眠组件。
- 合并 `desktop_menu.rs` 到 `shell_menu.rs`（若批次 A 之后仍需要）。
- `unwrap()/expect()` 收敛：DB/IO 路径改 `Result` 传播，只有真正不可恢复处才 panic。
- `build-release.sh` 纳入 `cargo test --lib`（+20 秒）。

### 批次 D — 文档收敛（低风险，随时可做）

- 重写 `PROJECT_STATUS.md` §0–§1 为**当前状态快照**（V101 基线），历史批次明细移到 `docs/04-review/history/`。
- `CONVENTIONS.md` 拆成「生效约定（≤300 行）」+「历史归档」，并加主题索引。
- 更新 `docs/README.md` 索引与阶段。
- 根目录 450 个残留**归档**到 `_archive/`（不删除）。

## 5. 风险与取舍

| 方案 | 风险 | 取舍 |
| --- | --- | --- |
| **批次 A（不接管）** | 需要程序化关闭「自动排列/对齐网格」，退出时还原；遥控图标位置在超多条目时可能有性能/抖动 | ✅ 换掉一个持续产 bug 的架构，**值得**。这是腾讯桌面整理走的路 |
| 仅做批次 C/D | 零风险，但**不解决根因**，下一轮反馈仍会落在 `grid.rs` | ⚠️ 只适合"暂时止血" |
| 保持现状继续打补丁 | — | ❌ 已被 60 个版本证伪 |

**明确的不可做项（需对用户说清）**：撤消删除、下一个桌面背景 —— Explorer 内部撤销栈与幻灯片引擎，
**无公开接口**，批次数再多也做不出来。
