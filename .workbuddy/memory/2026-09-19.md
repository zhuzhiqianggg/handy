### 踩到的坑（本轮新）

1. **镜像 first-fit 会回填空档，偏移量不是单调的**：写断言「左到右单调不减」必然失败 ——
   16 项的「文档」格旁边留出的空档会被后面 8 项的「其他」格填进去，这是**正确**的打包行为。
   改成断言「至少有一个格子贴到最右可用列」+「首格从右侧起（<= 2*pitch）」。
2. **被钉住的挂件（日历）右上角下方也可能塞进矮格子**：V41 那条「格子必须在挂件左边或正下方」
   在镜像模式下不成立，删掉，只保留「不与挂件重叠」+「挂件仍贴右边缘」。
3. **TS 判空**：`searchResults[0].id` 在 `length > 0` 守卫下仍判为 possibly undefined，
   必须写 `searchResults[0]?.id ?? null`；`payload.type === 'leave'` 要先 return 再访问
   `payload.position`（联合类型收窄）。
4. **`Edit` 工具的 old_string 一定要带足够上下文**：本轮一次 Edit 因 old_string 只取到行首的
   `- **端到端测试…桌面**` 而**误删了半行**，靠 tail 才发现。**教训**：改 md 这类长文件时，

## V44.2（12:55 用户报 bug：接管后关掉 Handy 桌面变空白）

### 用户原话
「handy 没有（运行/接管）的时候，原本的桌面图标全都不见了；工具打开并开启了整理 → 整理后的桌面；
工具没有开启桌面整理那么就应该桌面原本的样子，而不是乱搞」

### 根因
- 原生桌面图标（SysListView32）只在两条路径恢复：① `grid_overlay_hide`（用户主动收起挂件）
  ② `RunEvent::Exit`（进程真正退出时）。而 `RunEvent::Exit` 在拆解阶段之后触发，某些本机恢复已失效；
  且唯一触发退出恢复的是「托盘退出」（app.exit）。
- 用户关闭主窗口（X）→ `attach_close_to_tray` 只隐藏到托盘、进程照常运行 → 接管态（图标隐藏 + 挂件）仍在；
  若此时进程被杀 / 崩溃 / 卸载，Exit 不触发 → 图标永久藏起、挂件也没了 → **桌面空白**。
- 启动期 `heal_desktop_icons` 虽有兜底，但紧接的 `restore_overlay_if_visible` 会按接管偏好（takeover=1）重新藏起，
  所以「运行中=整理态」成立，但「不在运行=空白」是真实坑。

### 修复（仅 Rust 接管/退出路径，不动 UI/工具）
1. `restore_desktop_icons(app)` 改收 `&AppHandle`：恢复可见性 + 清 `icons_hidden` 标记 + 清 `ICONS_TAKEN`
   + 落日志（此前只调用 desktop_icons_apply，不清理状态）。
2. `lib.rs` 退出分支：`ExitRequested`（拆解前、进程全活，恢复最可靠）与 `Exit` 双接，均调 restore。
3. `app_quit` 在 `app.exit(0)` 前显式调一次 restore_desktop_icons —— 托盘退出这条最常用离场路径双保险。

### 行为模型（修复后）
- 整理 ON + Handy 运行中 → 整理态（图标隐藏、挂件在）= 桌面即主界面（V44）
- 整理 ON + Handy 退出 → 原生图标恢复（ExitRequested/app_quit 双保险）
- 整理 OFF（takeover=0）/ 未开 → 永远原生桌面（fresh install 默认 false）
- 关闭主窗口到托盘 → 仍运行中、保持整理态（设计如此，避免「挂件+原图标」双层）
- 硬杀/崩溃 → 下次启动 `heal_desktop_icons` 兜底恢复（仅限重新启动 Handy；彻底卸载且未优雅退出时
  图标需等 Explorer 重启才回，无法在卸载后补救）

## V44.3（09-19 下午 → 便携工具箱 / 隐藏后死路修复）

### 用户反馈
1. 点了「隐藏」后，桌面整理再也没入口能打开 —— **死路**。
2. 工具箱 + 密码存储器等直接挂桌面上是否可行？要一个「完美有效、合理方便」的**便携工具箱**。

### 根因（真死路）
- `grid_overlay_hide` 把**整个挂件窗 `win.hide()`**；而工具栏（搜索/工具箱/快捷/整理/隐藏按钮）
  就渲染在这个窗里 → 窗没了工具栏也没了 → 桌面无任何入口。
- 托盘菜单只有「打开 Handy / 设置 / 开机自启 / 退出」，**没有「显示/隐藏桌面整理」**。
- `grid_overlay_show` 命令虽已注册，但隐藏后 UI 里调用不到它。
- 工具栏**没有**独立「密码箱」按钮（密码箱只在搜索/快捷面板次级入口）。

### 方案（桌面优先，低风险）
**挂件窗始终显示（工具栏常驻），只有「格子内容」收起：**
- `grid.rs`：`grid_overlay_hide` **不再隐藏窗**，只收起内容 + 恢复原生图标 + `overlay_visible=false`；
  抽出 `ensure_overlay_window`（建窗/复用共用）；新增 `show_launcher_only`（不接管、只常驻工具栏）。
- `restore_overlay_if_visible`：**始终**显示挂件窗**（接管→`show_overlay`；未接管→`show_launcher_only`）**
  —— 首次安装 / 关掉桌面整理启动也是工具栏常驻，不再弹主窗口。
- `OverlayStatus` 加 `engaged`（= 内容是否接管）；`grid_overlay_status` 回带。
- `tray.rs`：新增「桌面整理：显示/隐藏」切换项，切换后 `emit_to(grid-overlay,"grid:visibility",engaged)`
  —— 托盘成为隐藏后的兜底入口。

**前端（`GridOverlay.tsx`）：**

### 诊断（这轮最值钱的部分：三条证据钉死机制）

用户原话：「点了下空白的地方桌面全都消失了，然后我到托盘里面点了下 handy，然后最小化 handy，

1. **读用户机 `handy.log`（523 行 / 11 次启动）做词频**：`Z 序不对（TooHigh）` **265 条**，
   单轮连续 5 次后「暂停 300 秒」；另有 8 条 `BelowDesktop`。→ 守卫一直在判、一直在纠、还纠不对。

   → 那一刻层级是**对的**，所以问题在判据/纠正动作，不是环境。
3. **新建 `scripts/audit/zorder-probe.py`**（复刻 `desktop_host()` + 走链）= `InDesktopBand`；
   再用**自建顶层窗**做 `SetWindowPos` 语义实验 → 得到两条真根因：

     靠「普通窗口不可能低于桌面」的钳制侥幸成立；命中「顶层 WorkerW」分支时会把挂件层推到
     **原生图标背后** = 用户截图里的「只有壁纸 + 回收站」。
   - **`reassert_takeover` 只看接管偏好、不看 `overlay_visible`** → 用户点「隐藏」交还图标后，
