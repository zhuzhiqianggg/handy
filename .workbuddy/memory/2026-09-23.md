# 2026-09-23（V69 · 「先把大格子算了布局好，然后把小格子找空隙插入」）

## 用户诉求（一张真机截图 + 一句话）

> 「现在好多了，不过格子的布局计算还是很垃圾，你应该先把大格子算了布局好，然后把小格子找空隙插入，
>  按照格子内容多少大小一次计算合理的位置放置 或者你有更好的方案你自己来实现规划」

截图现场：收纳区三列，**两个空的「新格子」坐在第一列顶端**，11 个条目的「文档」被顶到第二列。

## 根因（不是尺寸算错，是「谁排前面」错了）

V66 的 `balanced_partition` 是**保序切段**的 DP：先把序列切成 k 段、再让段高尽量均衡。
于是「谁排前面」= 谁登记的 `sort` 小 —— 空的「新格子」先建 ⇒ 先占住好位置。

⇒ 摆放序必须是「它们是什么」的纯函数，不能是「它们第几个出现」。

## 方案：LPT（Longest Processing Time First）

| 步骤 | 实现 | 对应原话 |
|---|---|---|
| ① 定摆放序 | `size_rank=(面积,内容量,高,宽)` 降序 → `placement_order`（稳定排序，完全并列回落到登记顺序） | 「按照格子内容多少大小」 |
| ② 分列 | `pack_columns`：每个格子放进**当前最矮的那一列**（并列取最左） | 「先把大格子算了布局好」 |
| ③ 填空隙 | 同 ② —— 最矮列 = 此刻最大的空隙 | 「小格子找空隙插入」 |

配套：`scatter_back`（内部按摆放序排，必须摊回调用方输入序）；`pick_columns`（列数从容量往下试）+ **第二趟「宽度夹 `zone_w/k` + 按新宽重算高度」**。

**幂等从「几何约束」升级为「算出来的」**：摆放序是内容的纯函数 ⇒ 尺寸没变 ⇒ 序没变 ⇒ 落位一字不差。
连带删掉沿用了四代的三条补丁：V64「manual 吸附最近的坑」、V66「读序 = 落位序」、V66.1「`(x,y)<=MARGIN` 哨兵」。

## 踩坑（三条，都被单测逮住）

1. **丢了 V66 的宽度夹取兜底** → 2 个端到端用例越界。真机收纳区只有 921 宽，18 个条目自然宽就 366，
   5 列要 1926px ⇒ 没有 k 装得下 ⇒ 整批溢出。加回第二趟解决。⚠️ 换算法时先问「旧的那条兜底还在不在」。
2. **面积会被分档吃掉差别** → 18 项与 16 项的自然宽都是 366、高都是 272 ⇒ 面积相同 ⇒ 退化成登记顺序
   ⇒ 还是「小格子压在大格子上面」（真跑到 x=519 那列）。⇒ `size_rank` 必须把**内容量**写进键里。
3. **过期的断言长这样**：`the_biggest_box_is_placed_first` 原来写 `order[1..3]==[0,1]`（两个空格子），
   加了内容量后 1 个条目的格子**正确地**排到空格子前面 ⇒ 用例红了。改的是断言，不是算法。

# V71（2026-09-23 下午·第二次）：布局「补丁感」= 少开了一列

用户 1 图 1 条：

> 「你看整体效果怎么还是**补补丁一样**的，三个图表最多的不应该 2 3 列上面开始平均放置，
> 然后把零散的少量的格子补在下面即可哇，至于便签这个列前面的空间不够再放」

## 先把「补丁」量出来

把真机那一组（收纳区 637×848、条目数 18 / 8 / 8）丢进 `content_plan` 单跑：

| 列 | 放了什么 | 下沿 |
|---|---|---|
| 第 1 列 | 「文档」(18 项) 一个 | 379 |
| 第 2 列 | 「其他」+「文件夹」两个摞着 | 875 |

第 1 列**空掉 501px**，第 2 列堆两层 —— 用户说的「补丁」就是这个。

## 根因：把「自然宽度放不下」当成了「这个列数不可行」

`pick_columns`（V69）从大到小试 k，**自然宽度装不下就直接淘汰这个 k**，而「夹到 `zone_w/k`」
那一趟要等**所有 k 都失败**才走：

| k | 自然宽度合计 | V69 判定 |
|---|---|---|
| 3 | 372 + 232 + 232 + 2×24 = 884 > 637 | 淘汰 |
| 2 | 372 + 232 + 24 = 628 ≤ 637 | **命中并返回** ⇒ 2 列 |

**宽度是软约束**（夹窄了格子变高，但还能用），**列数才是用户看得见的那个东西** —— 代码把
两者反过来了。

## 改法

把「夹到 `zone_w / k`」挪进 `k` 的循环**内部**，同一个 k 里**自然在先、夹宽在后**：

```rust
for k in (1..=capacity).rev() {
    let mut trials = vec![(natural_h, natural_w, false)];
    if capped != natural { trials.push((capped, true)); }
    for (hs, ws, capped) in trials { … 命中即返回 … }
}
```

* 能多铺一列就多铺一列 ⇒ 尺寸去适配列宽（不是少开一列让尺寸舒服）；
* 「自然在先」＝不夹也放得下时**不许**夹（只有 2 个格子时 `k = 3` 有一列是空的、不占宽，
  自然尺寸先命中）；
* 夹宽必须**同时按新宽重算高**（V69 已立的规矩，否则「后端算得下、前端还是滚」）。

改完真机那一组：**3 列并排、三格全在顶行**（文档 196×717，另外两个 196×347）。
5 个格子时：顶行正好是最大的三个，小的补在下面。
