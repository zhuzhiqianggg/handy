## 7. 架构约定（V18 / V19 确立，后续照此办）

- **rusqlite 参数个数必须与 SQL 占位符严格一致**：无 `?` 占位符就传空数组 `[]`，传 `0` 会报
  `Wrong number of parameters passed to query. Got 1, needed 0`（V18 桌面挂件全废的根因，
  见 `grid.rs::next_sort` 改用 `Option<i64>`）。
- **系统动作类功能一律走白名单**：`src-tauri/src/commands/sys.rs` 的 `table()` 是唯一事实源，
  前端只传 `actionId`；可执行目标/参数硬编码在 Rust，提权走 `Start-Process -Verb RunAs`。
  新增动作**只在该表追加**，禁止让前端拼命令串。
- **打开非 PE 目标只能走 `ShellExecuteW`**（V19 #1 的根因）：`.cpl`（控制面板）/`.msc`（管理单元）/
  目录/协议都不是 PE 可执行文件，`std::process::Command` 会报 `%1 不是有效的 Win32 应用程序 (os error 193)`。
  `sys.rs::launch_open` 用 `windows` crate 0.58 的 `Win32_UI_Shell::ShellExecuteW` 自主实现，
  返回值 `≤ 32` 视为失败（不依赖 `tauri_plugin_shell::open`）。
- **顶层浮窗用 Tauri 原生 `always_on_top`**（`bar.rs`），不要复用 grid-overlay 那套
  `SetWindowPos(HWND_BOTTOM)` + 光标命中轮询 —— 那套是「桌面最底层 + 点击穿透」专用。
  （V20 修正：`SetWindowPos(HWND_BOTTOM)` 实际会把窗口压到**壁纸之下**，桌面上根本看不见；
  桌面挂件真正贴到桌面的做法见 §8「桌面挂件」。）
- **主窗口默认不置顶**（V19 #5）：`tauri.conf.json` 的 main 窗口 `alwaysOnTop: false`，
  用户想驻顶由设置项 `settings.mainPinned` 决定。
- **窗口行为以设置项为单一事实源**：`settings.barPinned` / `settings.mainPinned` 由主窗口
  `main.tsx` 的 `useAppStore.subscribe` 驱动 Rust（`bar_show`/`bar_hide`、`app_set_pinned`）；
  订阅**必须限定 `windowRoot === 'main'`**（贴条窗也跑 main.tsx，不判断会自己叫自己）。
  `src/lib/store.ts::withDefaults` 负责补默认值，故旧 `settings.json` 缺新字段也安全。
- **用户可选集合一律「补默认值 + 忽略失效项」**（V19 #4）：`settings.quickActionIds`
  存自选快捷入口 id 数组，渲染时过滤掉已不存在的 id，缺字段回落到 `DEFAULT_QUICK_ACTION_IDS`。
- **笔记 UI 只在工作台**：`note-create`/`note-list` 命令收敛为「打开工作台」，TodoView 的
  「来源笔记」经 `useNotesStore.requestFocus` 定位（同窗口共用 store，无需 IPC）；
  `NoteWindow.tsx` / `NoteListView.tsx` 为休眠代码，无 UI 入口，勿再接线。
- **所见即所得 Markdown（`src/components/RichMarkdown.tsx`）**：输入用 `contentEditable` +
  输入事件里就地转换，对外**只暴露 Markdown 文本**（`Zustand/store/SQLite` 零迁移），只读展示走
  `MdText` / `renderMarkdown`。**改这个文件前必须先读组件头部的「浏览器内核踩过的坑」**（6 条），
  并按 §6 做逐字符回归。核心铁律：光标必须以**零宽哨兵 `ZWSP`（offset 1）**为落点、新块必须带
  种子、`marker` 必须先 `stripZwsp`、搬动节点后必须手动还原选区。
- **桌面整理是「文件引用型」**：格子条目只是原文件路径引用，**一键整理（`grid_auto_arrange`）也
  绝不移动/复制任何文件**；布局备份/还原存 `grid_meta`（key `layout:<uuid>`），还原前自动备份到
  `auto-before-restore`。这是用户明确要求（对标腾讯桌面整理，但不得产生磁盘副作用）。
- **浏览器冒烟**：`node scripts/dev-static.cjs 41901` 起静态服务指向 `dist`，配合
  agent-browser 深链 `?tool=<id>` / `?module=<id>` / **`?demo=richmarkdown`**；浏览器无 SQLite/Tauri IPC，
  「加载待办失败」「快捷入口需桌面环境」属预期提示，不是缺陷。
- **纯逻辑回归（V21 转正，V22 扩容到 4 套，V23 到 6 套 / 715 条断言）**：`src/lib/` 下不碰 React/DOM/Tauri 的纯模块
  （`cron` / **`cron` 平台判定** / `lunar` / `holidays` / **`sql`** / **`textlab`**）一律进
  `scripts/regression/run.mjs`（**6 套**：cron 114 · cron-platform 45 · lunar 32 · holidays 30 ·
  sql 357 · textlab 137；`test-sql.mjs` 一套 **357 条断言**）。**关键手法：Node ≥ 22.18 自带原生类型剥离，
  测试脚本直接 `import '../../src/lib/x.ts'` 即可，不要为测试引入 esbuild 打包步骤**（V21 最初就是手工
  esbuild 出 `_v21_*.mjs` 再跑，纯属自找麻烦）。加套件 = 新写 `test-<name>.mjs` + 加进 `run.mjs` 的 `SUITES`。
  这几个模块历史上都翻过车（cron 的 Quartz `N/step` 展开、lunar 的闰月游标漂移、sql 的「抹平用空格」导致误报），
  **改动后打包前必跑**。
  另：`holidays.ts` 的数据表用「全年逐日统计四类之和 = 全年天数（365/366）」当断言，能兜住区间写错。
- **面向用户当教材用的常量数据也要进回归（V22 新）**：`src/modules/toolbox/commands/sqlSamples.ts`
  里 30 条示例 SQL 是给用户照着学的，`test-sql.mjs` 末组断言要求每条 ①无 error 档问题 ②格式化后仍无 error
  ③至少识别出一个语法点。**示例本身出错 = 「学习指导」误人子弟**，所以教学数据要跟代码同一个标准守。

## 8. V20 确立的约定（工具基建 / 桌面挂载 / 贴条）

- **工具「示例条」是框架能力，不再各写各的**：`src/components/SampleBar.tsx` +
  `CommandShell` 的 `samples` 属性。每条示例自带 `apply` 闭包（可只填输入框，也可「填 + 开开关 + 切页签」，
  或一次设置多个字段）。示例条挂在**内容区之上且 `shrink-0`** —— `fill` 模式内容区是 `flex-1`，
  示例条必须是它的兄弟节点，塞进内容区会把输入框挤出可视区。新工具默认配 3–5 条示例。
  工具清单与逐工具优化方案见 `docs/03-development/TOOL-OPTIMIZATION.md`。
- **工具状态持久化用 `useToolState`**（`src/hooks/useToolState.ts`，localStorage、防抖 400ms、
  卸载 flush、256KB 上限）。已接：`cron-descriptor` / `regex-tester` / `text-diff`；其余约 3 行/工具。
- **结果区带高亮用 `CodeBlock`**（零依赖，按语言拼大正则扫 token）；Markdown 混代码块用
  `MarkdownWithCode`（按 ``` 围栏切分，未闭合围栏回退纯文本）。
- **文本对比对齐靠布局不靠事件**：单一滚动容器 + CSS Grid 两列 → 行对行对齐、滚动天然同步；
  虚拟空行 = `line === null` 渲染虚线占位块。**不要回到「两个独立容器 + 同步滚动监听」那套。**
- **贴条（`bar.rs` / `WorkstationBar.tsx`）**：
  - 高度由前端量出后经 `bar_set_height` 回报；`resizable(false)` 只拦用户拖拽，程序性 `set_size` 照常生效，
    但改高后**必须紧跟 `set_position()`** 才能保持顶部居中（Windows 以中心为锚点拉伸）。
  - 前端**必须外套一层 auto height 的「量高壳」**（`w-full`，不带 `h-full`）再量，否则
    「窗口高 → 量出窗口高 → 再设窗口高」会自激。展开态记忆在 localStorage（与主窗口同 origin）。
  - 折叠态与展开态共用同一份 JSX：折叠态包装层用 `display: contents` 让子块直接成为卡片 flex 项。
- **桌面挂件（`grid.rs`）**：~~真正「画在桌面上」= `SetParent(hwnd, 桌面宿主)`~~ ⚠️ **V21 已推翻**
  （`SetParent` 会丢逐像素 alpha 变灰块 + 触发窗口重建导致点击闪 + Explorer 重启后失效）。
  现行方案是 **顶层窗 + `SetWindowPos(hwnd, host, …, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)` 插在桌面宿主之上
  + `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`**，也**不是** `HWND_BOTTOM`（会掉到壁纸下面）。
  系统图标显隐走 `ShowWindow(SysListView32)`，
  **绝不移动/删除用户文件**；启动 `heal_desktop_icons`、退出 `restore_desktop_icons`（图标一定回来）。
- **windows crate 0.58 写法**：`FindWindowW/FindWindowExW` 返回 `Result<HWND>`
  （用 `.unwrap_or_else(|_| null_hwnd())`）；`SetParent` 第二参**不是 `Option`**
  （空父窗传 `null_hwnd()`，不是 `None`/`Some(...)`）。
- **ShellExecute 兜底链（`sys.rs`）**：`.cpl` → `rundll32 shell32.dll,Control_RunDLL`；
  `.msc` → `mmc.exe`；目录 → `explorer.exe`。返回码 **193 = 不是 PE**，**31 = `SE_ERR_NOASSOC`**（无文件关联）。
- **前端新文件过 `tsc` 后，lucide 图标名用 node 脚本比对 `lucide-react` 导出表**
  （`Settings`/`MonitorUp`/`PenLine`/`ChevronUp` 等实测都存在，别靠猜、也别靠旧版本印象）。
- **交互元素必须真有效**：V20 挖出 5 个「界面有入口、点了不生效」的假功能（假复制按钮、切换重置、
  冷启动空表、闭包竞态）。QA 检查项已加：**每个按钮的副作用是否真实发生**。

## 9. V22 确立的约定（布局防压盖 / 工具即教材）

- **网格里不允许 `min-h-*` 大于父格子**：V22「工作台挤在一起」的根因就是四层 `min-h-*`
  （网格行 440 + 计划 320 + 便签 `min-h-[420px]` 塞在 `h-[260px]` 壳里）同时超过可用高度，
  而网格项默认 `min-height:auto` **不会收缩** → 内容向下溢出自己的单元格，后渲染的面板把它盖住。
  **等高的正确做法**：父行给明确高度（`grid min-h-0 flex-1`）+ 子项 `min-h-0` + 把滚动条交给最内层；
  实在要保底就**让最外层内容列自己滚**（`flex min-h-0 flex-1 flex-col overflow-y-auto`），
  宁可出滚动条也绝不叠内容。新面板一律 `min-h-0 + overflow-hidden`，不要写 `min-h-[数字]`。
- **面向用户的「教学型工具」分三块落位（SQL 工具为样板）**：① **示例库**（分组 chip，点一条即填充，
  每条带 `takeaway` + `points` 讲解）② **实时检查**（分 error/warn/info 三档，每条必须给「怎么改 + 为什么」，
  只报错不给解法等于没写）③ **边用边学**（从当前输入自动识别语法点，点开一句话讲透）。
  **语法不是查来的，是在改自己那段时顺手看到的** —— 这是用户要的产品感。
- **检查器一律「宁可漏报也不误报」，且判据要跑在抹平后的文本上**：`lintSql` 先用 `maskSqlLiterals`
  把字符串/注释抹平（**填充符必须是 `\u0000` 这类非空白非单词字符，不能用空格** —— 用空格会让
  `in ('a', 'b')` 变成 `in (  ,  ,  )`，逗号「隔空」看到右括号而误报合法 SQL；同一个根因还误报
  `select a, 'x' from t` 与「末条是注释 = 缺分号」）。**代价**：凡判据依赖「后面跟着引号」的规则都会失效
  （`LIKE 'a%'` 已改为 `\blike\b`）。
- **格式化器只动换行与缩进，绝不改内容**：`formatSql` 先把字符串/反引号标识符/注释整段换成占位符，
  排版完成后再还原 —— 否则 `where name = 'from here'` 会被子句规则切开、`-- 注释` 会被折叠空白吃掉换行
  而吞掉后面整条语句。子句换行**必须单次交替匹配且长的排前面**（`LEFT JOIN` 先被插换行、再被 `JOIN`
  匹配到中间那个空格，会输出 `LEFT\n  JOIN` —— 这是真出过的事故）。
- **输入框不做输入期语法高亮**：桌面端 `contentEditable` 上色会在中文输入法下崩光标（V19/V21 已验证），
  所以 SQL 输入保持朴素 `textarea`，**高亮只出现在结果区**（`CodeBlock lang="sql"`）。别为了「好看」把
  这条推翻。
- **浏览器冒烟可以直接看工具页**：`vite` dev server + `agent-browser`，深链 `?tool=<id>`；
  但 **dev server 与浏览器必须在同一条 bash 调用 / 同一个 node 脚本里**（沙箱回收后台进程），
  且默认视口约 **1078×545**，比真机 1180×820 **矮 275px** —— 判读截图时要想到「挤」可能只是视口小。

## 10. V23 确立的约定（响应式 / 文本处理 / 平台标注）

- **响应式铁律：`flex-1` 在 auto 高度的父容器里不是「撑满」而是「可被压缩到 0」**（`flex-basis: 0%`）。
  窄窗口下它会先把内容压扁而不是产生滚动条 —— V23 实测 `CalendarPanel` 的 42 格网格被压到只显示 20 号、
  `PlanPanel` 被压成 19px 空壳。**要「撑满」必须给父级明确高度**；给不了就让内容自然排布、滚动交给外层。
  因此：**一切 `flex-1` / `min-h-*` 都用 `lg:` 前缀关进宽屏**，窄屏走「单栏 + 内容高度 + 外层滚动」。
  这与 §9「网格里不允许 `min-h-*` 大于父格子」是同一件事的另一面（一个管「撑爆」，一个管「压扁」）。
- **布局改动要跑数据，不要只靠眼睛**：`node scripts/audit/layout-audit.mjs` 对 24 工具 + 3 模块页 ×
  3 档视口（680/1024/1680）实测 `ox`/`mox`（横向溢出）、`clipX`/`clipY`（**内容溢出但不滚**）、
  `overlap`（**非祖孙块级矩形相交**）+ 截图。**只看溢出会漏掉所有真缺陷** —— V23 那两处 `ox` 全程为 0，
  只有 `clipY` / `overlap` 抓得到。参数：`--widths=` / `--only=` / `--shots`。
  dev server 与浏览器同前条，必须在同一条命令里。
- **文本处理类工具的换行必须全程带着走**：切行统一吃 `\r\n` / `\r` / `\n`，拼回时按原风格还原。
  直接 `split('\n')` 会在 Windows 文本行尾留 `\r`，于是「去重」把 `a` 和 `a\r` 当成两行 ——
  这是这类工具最经典的假 bug。`src/lib/textlab.ts` 的 `detectEol` / `splitLines` / `joinLines` 是标准解法。
- **同类操作用「数据驱动表 + 单个 switch」**：`LINE_OPS`（20 项 / 5 组）是唯一事实源，`applyLineOp` 是唯一
  switch —— 新增行操作 = 加一条数据 + 一个分支，界面与回归自动覆盖。别写成 20 个按钮各自 20 段逻辑。
- **平台方言要「标」不要「删」**：Quartz（6/7 段，Java / Spring / XXL-JOB 在用）不是冷门语法，
  真正的坑是「贴进 crontab 不报错、只是不跑」的静默失效。做法是 `platformOf()` 判定 + 常驻提示条 +
  误用自动变警示色，而不是砍掉功能。**判定必须精确匹配整段**（`L` / `5L` / `15W` / `1#2`），
  不能粗筛 `/[LW#]/` —— `JUL` 含 L、`WED` 含 W，粗筛会把最普通的写法误报，假警报比不提示更糟。
  回归里必须有**反向用例**（`test-cron-platform.mjs` 守着 JUL/WED/SAT 不得报警）。
- **重复 UI 面板要敢于删、但要把独有信息内联走**：V23 删掉 Cron 的「字段拆解」前，先确认它与逐段编辑
  渲染的是**同一份数据**，再把它独有的两样（展开取值、出错定位）并进保留的那个面板。
  判断标准：**同一份数据的两种排版 = 内容重复，删；独有信息是另一回事，搬走**。
- **体量大的功能必须给分阶段范围与优先级**：用户提「参考 Notepad++ 的文本处理」时明确要求说明工程体量
  并分阶段。做法见 PROJECT_STATUS §1.9.3 —— Phase 1 只做「纯字符串变换、能进回归」的部分（价值密度最高
  且正确性可证明），Phase 2 做「把单次操作升格成可重复流程」（批量 / 配方 / 巡检报告），
  Phase 3 明确**不做**（编码互转要自带码表、超大文件要换架构、列块框选是编辑器工程）。
  **产品主张是「方便，而非全面」——做半个 VSCode 不如把 24 个工具都做扎实。**

## 11. V24 确立的约定（视觉令牌 / 工具分类 / 自检体系）

- **现代化视觉的杠杆点是设计令牌**：页面底色 `--canvas`（浅灰）+ 白色卡片的层次、更大圆角、柔和阴影、
  统一动效时长定义在 `src/index.css`，`tailwind.config.ts` 加 `canvas` 色与更现代字体栈。
  **改令牌 = 一次改全局，别逐个页面调颜色。**
- **工具箱从「平铺」升级为「分类分组」**：`CommandMeta.category` 是必填项。取值联合类型在
  `src/core/types.ts` 的 `ToolCategory`，元数据（名称 / 图标 / 配色 / hint / 顺序）在
  `src/core/toolCategories.ts`，**两边必须一一对应**（`tool-audit` 双向校验）。当前 6 类：
  `text` / `data` / `encode` / `convert` / `generate` / `dev`。**加工具必须填分类** ——
  没分类 = 首页分组里没有它的位置 = 新工具被埋掉。
- **状态持久化有两个 hook，按「状态长什么样」二选一**（`src/hooks/`）：
  - 状态本来就集中在一个对象里 → `useToolState(id, initialObject)` → `[state, patch, reset]`；
  - 状态散在多个 `useState` 里（工具箱绝大多数工具如此）→ `usePersistedState(id, key, initial)`，
    **签名与 `useState` 完全一致（含函数式更新）**，迁移只需改声明那一行，调用点一行都不动。
    V24 就是这么把 19 个工具的 80 个字段一次性接上的（脚本化替换 + 逐行断言，不手改 19 个文件）。
  - **三类绝不持久化**：派生结果（格式化输出 / 摘要 / 二维码 dataURL）、大块 Base64 正文、
    **密钥类输入**（WiFi 密码 / JWT secret）—— 落盘 = 明文写进用户目录，与「保险箱加密存储」自相矛盾。
- **「易扩展」靠三件套把「漏配」变成机器能发现的错**（都在 `scripts/`）：`new-tool.mjs`（一键生成
  组件 + 注册项 + 关键词补齐）、`audit/tool-audit.mjs`（静态自检：图标已登记 / category 合法 /
  组件文件存在 / 名称与描述长度 / 关键词 ≥5 / 示例条 / 状态持久化）、`docs/03-development/TOOL-AUTHORING.md`。
  **自检第一次运行就抓到 3 个工具的图标从未登记** —— 它们一直在静默显示扳手，肉眼永远发现不了。
- **自检的提示项允许「显式豁免」，不允许静默缺失**：文件里写 `// tool-audit-ignore: samples`（或 `persist`）
  并说明为什么不需要（正则库 / 示例 token 生成 / 图片工具没有可填输入）。
- **示例条里的值必须真算过**：哈希 / Base64 / 时间戳全部用 `node -e` 实算后写入。手编一个「看起来像」
  的摘要，用户点开校验会直接对不上 —— 比没有示例更糟。**同理，冒烟断言里的字面量也要对着数据核一遍**
  （V24 它先报了一次假失败：断言写 `books`、而 `SAMPLE_JSON` 里字段是单数 `book`）。
- **同一份内容不要存两份**：补 JSON 工具示例条时又写了一份 `SAMPLE_NESTED_JSON`，而文件里早有 `SAMPLE_JSON`
  —— 与 V23 的 Cron「字段拆解」同一类重复。判断标准见 §10：**同一份数据的两种排版 = 删，独有信息搬走**。
- **并排断点要与「工具页预设宽度 1180」对齐**：用 `lg`(1024) 而不是 `xl`(1280)，否则默认窗口尺寸下
  双双退化成单列、右边一大片空白（V24 修了 JsonFormatter / QrCodeGenerator）。
- **删结构化文本（JSX 块）前先数清首尾行**：V24 用 `splice(idx - 1, 3)` 删按钮块，把外层的 `<div>`
  一起删了，`tsc` 报出一堆「JSX 标签不匹配」。删完立刻 `tsc`，别攒着。
  **迁移 / 替换脚本的自检条件要盯「独立证据」**（如 import 行开头），别盯刚被改写过的位置 ——
  V24 的 import 插入判断写在替换后的行上，判定恒真 → 18 个文件一句都没插上。
- **`tool-audit` 证明不了「点下去真的生效」**：它只能静态看到 `samples=` 写了没有。于是 V24 转正了
  `scripts/audit/sample-smoke.mjs`（真实 dist + 无头浏览器逐个点示例 chip，回读输入框与页面正文断言，
  **连填完以后派生结果算不算得出来一起验**）。**三件套分工：tool-audit 静态、layout-audit 量几何、
  sample-smoke 真点。**

## 12. V25 确立的约定（反馈即缺陷 · 示例自洽 · 真桌面自证）

### 12.1 「用户能一眼看出来的错」= 我们的验证面缺口

V25 的三条反馈（密码符号太多/连排、正则示例零命中、桌面整理疑似假动作）**都不是偶发 bug**，
每一条都对应一个**从未被任何脚本覆盖**的面。定规矩：

- **凡是「示例」都要能被机器判定对错**。正则库的教训：示例文本和正则各写各的、没人验，
  30 条里错一片也看不出来。→ `regexLibrary.ts` 每条声明 `sampleKind:'text'|'list'`，
  `sampleHitCount()` 算出命中数；界面 `HitBadge` 直接显示「N 处 / 示例不匹配 / 正则无效」，
  回归 `test-regex-library.mjs` 守「**每条正则在自己示例里必须有命中**」。
- **整串校验类正则一律 `^...$` + `m` 标志，配「候选清单」样本**（每行一个值，刻意混入非法值）
  —— 这样一行对一行、错在哪个值上一目了然，而不是整段文本零命中。
- **能数学证明的就别用循环试**。密码「符号不连排」不是靠 retry，而是靠**同奇偶位置互不相邻**的
  性质构造（`separatedPositions`，容量上限 `Math.ceil(n/2)`）——可证、无偏置、不死循环。
  删掉组件内联的近似实现，`passwordGen.ts` 是**唯一核心**（两份实现必然漂移）。
- **「动了真磁盘」要让用户看得见**：`OrganizerView` 顶部常驻「作用目录」栏，直接显示
  `scanDesktop()` 回来的真实路径 + 条目数 + 打开按钮 —— 用户不用信我们的措辞，看路径就知道。

### 12.2 桌面整理：两套能力别混在同一个入口

- `organizer.rs` = **真移动文件**（`dirs::desktop_dir` 认 OneDrive 重定向、按类型/日期分目录、
  **同名不覆盖**、跳过隐藏/系统/lnk、撤销按可逆序还原）。
- `grid.rs` = 桌面悬浮格子层。**V33 起也是真移动**：格子绑定真实目录
  `桌面/Handy整理/<格名>/`，拖入即 `fs::rename`；**V25–V32 那套「只登记引用、零磁盘副作用」
  的模型已作废**（正是它造成「复制了一份」的观感，见 §13.1）。
- 二者能力完全不同，却曾把入口指向 `grid` → 用户观感即「只在自己框里玩」。
  **定规矩：入口默认必须是「真动作」的那个**；想保留的另一套用 `embedded` prop 做成页签
  （`DesktopOrganizerConsole.tsx`），并在页签旁**一句话说清动不动文件**。

### 12.3 浏览器脚本四条硬规矩（V25 实测踩出）

1. **首次 `open` 会冷启动无头浏览器，实测 60~90 秒**。给它 180s 超时，或开局先做一次预热
   open（`layout-audit` 的 `WARMUP_TIMEOUT`）。拿 60s 固定超时去调它 = 每轮都把冷启动掐断在
   半路，后面每步都慢到超时，**整轮看起来就像卡死**。
2. **别用 `agent-browser wait --load load`**：open 之后 load 事件早已触发，它只能等自己的超时
   → **每页固定空烧 25 秒**。改成在页面里轮询就绪（`for (i<50 && 未就绪) sleep(200)`）。
3. **`input[type="text"]` 匹配不到没写 `type` 的 `<input>`**（属性选择器只匹配显式属性）→ 会漏读
   输入框、报出完全虚假的「没填进去」。选择器写 `textarea, input`。
4. **别用 `spawnSync` 调浏览器 CLI**：冷启动时子进程继承 stdout 管道，`spawnSync` 要等管道关闭
   （= 等浏览器退出），**它自己的 timeout 也救不了**。改 `spawn` + `exit` 事件 + 自计时 + `SIGKILL`。

另两条配套：注进页面的探针函数要用 `String(fn)` **原样注入**（手写进模板串会被模板串吃掉转义，
`\s` → `s`）；逐条写日志**边跑边落盘**（全跑完才写的话，卡死时日志是 0 字节，等于没有诊断）。

### 12.4 断言自检：逐条追问「它有没有可能必然成立」

`body.includes('天前')` 因为示例 chip 标签本身写着「3 天前」而**恒真**，测了个寂寞。
**定规矩：写完断言后逐条反问「这个条件在失败场景下会不会也成立」**；时间相关的断言要从
`Date.now()` 重算期望值再比对，**别写死数字**（示例用固定日期串，天数会随日漂移，次日必假失败）。

## 13. V33 确立的约定（真实收纳模型 · 节流自愈 · 安全脚本）

### 13.1 「桌面层显示的东西」与「磁盘上的东西」必须是同一份

V30 的「自动收录」把桌面文件登记成**引用**，文件本体留在桌面根 → 同一批文件在桌面和格子里
各显示一份，用户的原话是「**并不是整理收纳，而是复制了一份而已**」。

- **定规矩：任何「把东西收进容器」的功能，容器必须绑真实目录，收纳 = 真移动**。
  只有当磁盘上真的少了一份，用户才认这是整理。
- **禁止默认自动收纳**：自动搬迁用户文件必须有**显式动作 + 二次确认**，且报告里要说清
  「扫了多少 / 搬了多少 / 跳过多少 / 失败多少」——跳过项要单列，否则用户以为漏了。
- **快捷方式（`.lnk`）与文件夹默认不动**（用户明确要求）。要动必须单独开关。
- **登记表不是真相**：磁盘目录是唯一事实源，DB 只缓存 id 供前端做删除/移动定位。
  每次列举都 `reconcile` 对齐（两侧都能改：程序搬、用户在资源管理器里手工拖）。

### 13.2 走「自愈」这条路之前，先证明判据不会被环境伪造

V32 的自愈是「窗口可见 + 90s 没心跳 → 判定 webview 死 → 销毁重建」，结果
**WebView2 对贴在桌面层的窗口会节流定时器**，心跳自然超过 90s → 自愈机制周期性误触发，
用户看到的是「闪一下没了，过会儿又出来」。

- **定规矩：自愈的触发判据必须区分「本来就慢」和「真的死了」**。这里的正解是
  「**显示后从未收到任何一次心跳**」（只治冷启动白屏）+ 冷却窗口 + 重建次数上限。
- 涉及**第三方程序也会抢的资源**（窗口 Z 序、图标层）时，单次不匹配不足以行动：
  要求**连续 N 次**不匹配再纠正，并把校验周期从秒级放宽到十秒级。

### 13.3 频繁变化的值不要进 effect 依赖

便签自动保存写成 `useEffect(() => () => flush(draft), [flush, draft])` → 依赖里有 `draft`
就会**每敲一个字重挂一次 effect**，cleanup 每次都在当前这一笔上跑一遍有副作用的 flush：
既造成「每字符一次 IPC + 写库」，又把刚设好的防抖定时器取消掉。

- **定规矩：effect 依赖里出现「每次输入都变」的值时，必须反问「这个 effect 的 cleanup
  会不会在每次变化时都执行一遍带副作用的动作」**。需要「卸载时用最新值」就上镜像 ref
  （`draftRef` / `onSaveRef`），让依赖保持稳定。

### 13.4 打包的 shell 环境必须显式构造（本机沙箱特性）

WorkBuddy 的 bash shim **会假成功**（日志十几字节、产物 mtime 不变），且沙箱内 coreutils
大面积缺失：`dirname` / `stat` / `xargs` / `cygpath` / `grep` / `tail` / `du` / `sed` **全 MISS**，
`find` 还会解析到 Windows 的 `find.exe`（参数语义完全不同，`find dist -type f` 直接报错）。
`scripts/build-release.sh` 内部大量使用这些命令，**必须**这样跑：

```bash
PG=/c/Users/Administrator/.workbuddy/binaries/PortableGit/versions/1.2.0
"C:/Users/Administrator/.workbuddy/binaries/PortableGit/versions/1.2.0/bin/bash.exe" -c \
  "export PATH='$PG/usr/bin:$PG/mingw64/bin:$PG/bin:<node-dir>:/c/Windows/system32:/c/Windows'; \
   cd /d/_Projects/ops/handy; bash scripts/build-release.sh > .build-logs/run.log 2>&1"
```

- **PATH 里的路径必须写 POSIX 形式 `/c/...`**：写成 `C:/...` 时 MSYS bash **不认**，
  coreutils 全部消失（表现为脚本第 25 行 `$(dirname …)` 失败）。这一条试错花的时间最多。
- 用 `-c` 传一整个字符串、内部再 `bash scripts/xxx.sh`（而不是让外层直接执行脚本文件），
  这样 PATH 注入对脚本及其子进程都生效。
- 中途 kill 掉正在跑的 build **不会**留下 cargo 残留进程，cargo fingerprint 能自愈，
  直接重跑即可（不必等、不必清 target）。

### 13.5 判断「新版本坏了」之前，先拿一个已知 good 的旧产物做对照

V33 装机后出现过一次**几乎走错方向**的排查：安装完成的程序「进程存活」但窗口起不来、数据库一个字节
不写 → `schema_migrations` 停在 v5、`grid_boxes` 没有 `kind` 列，看起来**像 V33 把迁移写坏了**。
实际是**当前会话环境已无法启动这个 GUI 应用**；用一个两天前的旧产物一跑就水落石出。

- **定规矩：怀疑「新版本回归」时，第一步是拿旧产物做对照，不是读新代码。**
  `%LOCALAPPDATA%\Handy\handy.exe.zombie`（NSIS 在文件被占用时重命名的旧主程序）就是现成的对照物 ——
  复制到 TEMP 单独跑一次即可。旧产物也挂 ⇒ 环境问题，立刻停止盲改。
- **「进程存活」不等于「启动成功」**。附一个廉价的健康判据：真 Tauri + WebView2 进程工作集应在
  **100 MB 量级且持续增长**；如果内存**恒定不动**（26–39 MB）、线程数固定、CPU 时间冻结，
  那是卡在启动早期，别拿「tasklist 里有进程」当通过。
- **数据层症状要先和「数据层」分开验证**：把有疑问的 SQL 拿到**真实库副本**上单独执行
  （python `sqlite3.executescript` 即可），能在不碰应用的前提下判定 SQL 本身对不对。
- **动用户数据前必须留退路，且还原动作要用最不容易被拦的方式**：本次隔离实验（把 `handy.db` 移开、
  用空库启动）中途 PowerShell 的 `Remove-Item`/`Move-Item` 被安全层拦掉，用户库一度停在
  `handy.db.aside`。教训：① 先 `Copy-Item` 备份到 TEMP；② 还原优先用 `node fs.renameSync` 这类
  文件 API，而不是 PowerShell 的 Move/Remove；③ 还原后**比对 sha256** 确认逐字节一致。

## 14. V34 确立的约定（窗口层级 · 驻留语义 · 复用而非复制 · 整类跳过）

### 14.1 同一模块收到两条**相反**的抱怨时，先假设它们是「同一个机制的两端」

V34 用户同时抱怨「格子**盖在我其他窗口上面**」和「**点别的地方格子就消失**」。看起来互斥，
实际是**一条因果链**：

> `show_overlay()` 里先 `apply_attach()`（按基准层插到桌面正上方）、**再** `show()` ——
> 而 `show()` 会把窗口提拔到 **Z 序顶层**，刚贴好的层级当场被顶掉。

顶上去了 = 第一条；它虽在顶层却**不是激活窗口**（`make_unfocusable` 不抢焦点），用户点任意别的窗口，
那个窗口被激活盖过来 = 第二条。**修法就是调换两行顺序。**

- **定规矩**：遇到相反的两条抱怨，先画一遍「系统状态随时间怎么变」，多半是同一条链。
  当成两个 bug 分别修，会把这两行代码越改越乱。
- **推论（一般化的窗口层级规矩）**：Tauri/任何窗口 API 里，**「改变可见性」的调用都会顺带改 Z 序**。
  凡是「贴到某个基准层」的实现，`show()` / `set_focus()` / `set_always_on_top()` 一律排在
  「按基准层归位」**之前**，归位必须是最后一步。
- 排错时把**三个句柄**（自己 / 基准层 / 自己正下方是谁）一并落日志 ——
  一行就能区分「attach 压根没生效」和「被别的窗口插队」。

### 14.2 「驻留」语义必须显式化，并与用户的预期对齐

用户对桌面挂件的心智是「**它就是桌面的一部分，除非主程序退出**」。而实现把「窗口不在」一律当成
「收工」→ 轮询线程 `break` 退出，一次意外之后永久不管了。

- **定规矩**：凡是**常驻型 UI**（桌面挂件 / 托盘 / 贴条），「窗口/线程消失」都要区分两种语义：
  **用户主动收起**（应退出）与**意外丢失**（应恢复）。用一个持久化的意图位
  （本项目 `grid_meta.overlay_visible`）作为唯一判据。
- 自愈必须带**冷却 + 次数上限**（本项目 30s 冷却），否则会变成「销毁-重建风暴」——
  而风暴本身就长着「闪一下没了又出来」的脸，和它要治的毛病难分。
- 自愈判据要**尽量便宜**：把「该不该重建」降到约 30 秒判定一次（`missing_ticks % 500`），
  别在 60ms 轮询里每次都查库。

### 14.3 用户说「XX 根本不生效」时，先搜这三样：`continue` / 直白实现 / 老 API

V34 四条「不生效」全部是这三类，**都不是「功能写坏了」**：

| 用户说法 | 真根因 | 类别 |
| --- | --- | --- |
| 「文件夹的整理根本都不生效」 | `auto_arrange_inner` 里 `if item.is_dir { continue }` | **整类被跳过** |
| 「便签怎么就一个纯文本框了」 | `NoteWidget` 用了裸 `<textarea>`，而项目里早有 `RichMarkdown` | **直白实现**（没复用现成能力） |
| 「整理到格子里的图标样式都变了」 | `SHGetFileInfoW(SHGFI_LARGEICON)` 只给 32×32，桌面「中等图标」是 48×48 | **老 API** |
| 「我的电脑有两个」 | 「此电脑/回收站」是 Explorer 的**常量条目**，格子再画一份 = 与系统固有绘制重复 | **与系统固有绘制重复** |

- **定规矩**：「不生效」优先按「被跳过 / 没复用 / 用错 API / 和系统重复」四个方向查，
  比通读业务逻辑快得多。

### 14.4 同一个视图出现在两处时：**复用纯函数与数据表，绝不复制 UI**

桌面日历挂件要求「跟工作台一模一样」。正确做法是先读工作台实现，发现它的可复用部分早就抽在
`src/lib/lunar.ts`、`src/lib/holidays.ts`、`planUtils.buildMonthGrid/isSameDay` 里 ⇒ 挂件直接调同一批函数，
于是**农历/节气/节日/休班/干支天然逐项一致**，不存在「两处实现漂移」。数据同样复用同一张 `todos` 表
（`detail` 承载描述）。

- **定规矩**：新增一处「看起来像另一个页面」的 UI 前，先问「它的纯逻辑抽出来了吗」。
  已经在 `src/lib/` 里的就直接调；没有就先抽再调。**复制一份 UI 出来 = 签下了一张长期漂移欠条。**
- 顺带：`addWidget` 这类「可无限添加」的按钮要**幂等**（已存在同类就置灰），而不是点了才弹提示。

### 14.5 windows-rs 0.58 的三个签名坑（改 Windows 系统图标这条路）

1. `IImageList` 在 `Win32::UI::Controls`，**必须在 `Cargo.toml` 额外开 `Win32_UI_Controls` feature**（否则 E0432）。
2. `SHGetImageList(size)` 是**泛型返回** `Result<T>` —— **一个参数**，不再手写 IID
   （旧写法 `SHGetImageList(size, &IID_IImageList, &mut ptr)` → E0061）。
3. `IImageList::GetIcon(i, flags) -> Result<HICON>` 是**返回值式**签名（老版本是 `&mut HICON` 出参），
   `flags` 要**裸 `u32`** ⇒ 写 `ILD_TRANSPARENT.0`。
   另外 `SHGFI_*` 组合要包 `SHGFI_FLAGS(...)`；`DestroyIcon` 在 `Win32::UI::WindowsAndMessaging`。

> 要 48×48 + `.lnk` 箭头叠层，走 `SHGFI_SYSICONINDEX` + `SHGetImageList(SHIL_EXTRALARGE)`；
> 退路是 `SHGFI_ICON | SHGFI_LARGEICON`（32×32）。两者都要带
> `SHGFI_LINKOVERLAY | SHGFI_ADDOVERLAYS`，否则快捷方式没有小箭头，和桌面观感对不上。

### 14.6 装机收尾：**装完即止**，且不代为启动

本会话起不来本 GUI（§13.5 / PROJECT_STATUS §1.19.2）。V34 起明确**不代为启动**：

- 强行启动只会在任务管理器留一个僵死进程；本项目有**单实例插件**，用户自己双击时会被引导去
  「聚焦」那个僵尸，反而变成「点了没反应」——比不启动更糟。
- **定规矩**：`build-release.sh` 用 `--no-deploy` 只构建，装机与取证**手工做**（可控且能逐字节比对）；
  回复里明确写「请你自己启动」。
- 取证优先级：**逐字节比对**（只应差 Tauri bundle 标记那 3 字节，`cmp -l` 即可，明细留档）
  > mtime（只能证明「变新了」）。

## 15. V35 确立的约定（系统级行为对抗 · 采样率与命中区 · 就地编辑）

### 15.1 对抗系统级行为（Win+D / 最小化全部窗口）：**别改窗口类型，改成「检测 + 立刻还原」**

Win+D 的语义是「给**所有顶层窗**发一条最小化」。挂件层虽然被 `place_above_desktop` 插在桌面正上方，
但它**不是桌面的子窗口** —— 在 Win+D 眼里它就是个普通窗口，一样被最小化。

| 方案 | 代价 | 结论 |
| --- | --- | --- |
| `SetParent` 挂成桌面/WorkerW 的子窗口 | **坐标体系变成相对父窗**（所有绝对定位逻辑要重写）；Explorer 重建 WorkerW 时会连带我们 | ✗ |
| 轮询判 `IsIconic` → `SW_SHOWNOACTIVATE` 还原 → 重贴路径 | 25ms 一次判断，用户感知不到；只动 Rust 一侧 | ✓ |

- **定规矩**：遇到「系统会统一处理所有窗口」的行为（Win+D / Win+M / 显示桌面 / 全屏切换），
  优先想**「怎么在被处理之后马上恢复」**，而不是**「怎么让系统不处理我」**。后者几乎总是要改窗口类型
  （子窗口 / tool window / 无激活），代价是坐标体系、焦点、Z 序全线连带，会把已有代码全泡一遍。
- 还原要**不抢焦点**（`SW_SHOWNOACTIVATE`），否则用户按 Win+D 是为了看桌面，结果焦点被我们截走。
- 还原之后**当轮跳过其它判定**（穿透 / 心跳），拿中间态做判断会产生假警报。

### 15.2 挂件窗「平时穿透、按坐标放行」的架构 ⇒ 鼠标感知由**采样率**和**命中区**两个旋钮决定

本项目挂件窗默认 `ignore_cursor_events(true)`（否则整块桌面都点不动），
**能不能点到格子完全由 Rust 按全局光标位置判定**。这个架构下「鼠标移上去没识别」不是逻辑错，
是**离散采样追不上连续移动**：

- **定规矩**：这类「按坐标放行」的实现，`POLL_INTERVAL_MS` 是**手感参数**而不是性能参数，
  必须够快（本项目 V35 由 60ms → **25ms**）。
- **定规矩**：命中区**必须比视觉边界外扩**（[`HIT_PADDING`] = 4px）。外扩不是为了好点，
  是为了**补掉「采样间隔内鼠标已进入但窗口还没切到可交互」的窗口期** —— 手越快越明显。
- 两个旋钮要一起动：只提速不扩边，手快时仍会漏；只扩边不提速，鼠标停在格子上时依旧要等一个周期。

### 15.3 八向缩放的两个必然细节（少一个就会出现「方向跳」或「反向长大」）

1. **边手柄必须在两端让位给角手柄**：四边各占一条 6px 命中带，但用 `left-3 right-3`（上下边）
   / `top-3 bottom-3`（左右边）把两端各留 12px 给角。否则角上同时命中「边」和「角」两个元素，
   拖起来方向会跳。
2. **`n` / `w` 两条边缩放时原点必须跟着移**：不是单纯改宽高 —— 往左拉要把 `origX` 一起左移，
   否则视觉上变成「往右长」。`Interaction` 里要同时存 `origX/origY/origW/origH`。

> 顺带：重叠格子点不到被压住的那个 ⇒ 交互开始时 `sort = max(sort)+1` 抬到最上层。
> **只在「开始拖动/缩放」时抬，不做成「点一下就抬」** —— 后者每次单击都写一次数据库。

### 15.4 用户**改口**时，要改的是「一个决定」，不是「一行代码」

V34 用户要求「便签也一个吧」，V35 又说「便签应该可以添加多个」。这类改口的坑在于**决定散落在多处**：

| 位置 | V34 留下的东西 |
| --- | --- |
| `GridOverlay.addWidget` | 幂等拦截 + 按钮置灰 |
| `GridManagerView.addWidget` | **另一份**幂等拦截（实现还不一样：一个置灰、一个点了才提示） |
| 管理页说明文案 | 「便签与日历各只能有一个」 |
| 管理页空态文案 | 「各限一个」 |
| doc comment | 「同类型全桌面只允许一个」 |

- **定规矩**：用户改口后，先 `grep` 上一版决定留下的**措辞**（本项目：「各限一个」「只允许一个」
  「已经有一个了」），把这些命中的**每一处**过一遍，而不是只改那个按钮。
  **注释/文案里的旧决定，比代码里的旧决定更容易漏**，而它恰恰是下一个人（或下一轮的我）的判据来源。
- **定规矩**：同一能力出现在两处（桌面浮层 / 管理页）时，**新规则要在两处写出相同的代码形状**
  （同样的自动命名、同样的配色轮换），不要一处一个样 —— 否则用户从哪边加的东西不一样。

### 15.5 「提高对比度」与「边缘自然融合」不是矛盾的 —— 用**渐变 + 柔影**而不是**边框**

用户同时提「透明背景后有点模糊，怎么增加对比度」和「边缘自动融合桌面背景」。硬边框只会解决前者、
破坏后者。做法：

- **中心足够暗**：`rgba(12,14,22,0.62) → 0.46` 线性渐变（按 accent 微微染色），文字压在上面就清晰了；
- **四周没有边界**：**不加 border**，靠**大而柔的投影** + **顶部 1px 高光**把边缘「化」进壁纸；
- 渐变方向按 accent 走，保证换配色后整体色调仍协调。

> 定规矩：桌面挂件这类「浮在壁纸上」的卡片，**先无边框、后用光影**。一旦上硬边框，
> 视觉上立刻从「画在壁纸上」退回「贴在壁纸上的窗口」。

### 15.6 「内容自撑高」与「用户手动缩放」的冲突：守卫要记**当时的内容高度**，不能只记一个布尔

日历要求「计划区随条数动态撑高」，但用户可能手拉着改过高度。若守卫只记
「用户手动改过 ⇒ 永不自撑」，那内容后来变多了也不会撑；若只记布尔不记高度，
用户手动缩小后下一次测量会立刻把它弹回去。

- **定规矩**：记下**「用户手动缩放那一刻的内容自然高度」**（`autoHeightBlockedRef: Map<id, natural>`）。
  之后只有**内容高度真的变了**（Δ 超过阈值）才重新接管自动撑高 —— 用户那次手动调整被尊重，
  而新内容依然撑得开。
- 自动撑高**必须有上限**（本项目 `window.innerHeight × 0.7`）：一条很长的计划不该把格子撑到全屏。
- 测量走 `scrollHeight` 时，根元素要 `overflow-hidden`、子元素高度 auto，否则量到的是视口而不是内容。

### 15.7 挂件要用工作台的逻辑 ⇒ **抽进 `src/lib/` 再 re-export**，不要反向依赖

日历挂件要复用工作台的日期运算/纪念日逻辑，但这些函数住在 `modules/workstation/planUtils.ts` ——
直接 import 会让 `desktop-grid` **反向依赖 `workstation`**，而且同一份日期口径出现两份实现（迟早漂移）。

做法：搬进 `src/lib/dateUtils.ts` / `src/lib/anniversaries.ts`，在原文件里
**从 `@/lib/...` 引入并原样 re-export** ⇒ **调用方一行都不用改**。

- **定规矩**：跨模块复用纯逻辑时，落点是 `src/lib/`（本项目从 V18 就定的分层），
  并且**用 re-export 保持旧导出名**，把改动面收敛到「一个文件 + 一个 import」。
  直接跨模块 import 只适用于「上层调下层」，`modules/A → modules/B` 一律不许。

## 16. V36 确立的约定（自检判据 · 自愈保险丝 · 看不见屏幕的诊断法）

### 16.1 用户说「闪」时，先去找「有没有一个循环在反复做同一件事」

「闪一下就没 / 有时又出来」这类描述，**不要**从渲染、透明、WebView2 去猜。
第一步永远是：**去应用自己写的日志里数行数**。

V36 的现场日志（`%LOCALAPPDATA%\Handy\grid-debug.log`）从 11:54:48 到 11:56:33
**连续 90 多行完全相同**：

```
Z 序错位（连续两次；我正下方不是桌面窗口），重新贴回桌面层（overlay=… host=… below=…）
```

一行不用推理：**每次自检都失败、每次都重排一次** ⇒ 闪烁的真正来源就是那个循环本身。

- **定规矩**：项目里凡是**周期性**动作（自检 / 自愈 / 重排 / 重建）都**必须留一行可数的日志**。
  排查时「行数 × 间隔」直接给出循环频率，比任何猜测都快。
- **定规矩**：报「闪烁/抖动」类缺陷时，**先问用户要那行日志**（或直接读安装目录），
  不要先改渲染参数。

### 16.2 自检的节奏**绝不要**写成「多少个轮询周期」

V34 写的是 `REASSERT_TICKS = 40`，含义随 `POLL_INTERVAL_MS` 走：当时 60ms × 40 ≈ **2.4 秒**。
V35 为了拖拽手感把轮询提到 **25ms** —— 同一个 `40` 悄悄变成 **1 秒**，
自检频率翻了 2.4 倍，而**两边代码都看不出这件事**。用户侧的观感就是「一直闪」。

- **定规矩**：周期性动作的间隔一律用**时间量**（秒），不要用「第 N 个 tick」。
  轮询周期是**手感参数**，和自愈节奏是两件事；用 tick 计数就是把它们焊在一起，
  以后任何人调手感都会无声地改掉自愈。
- 推论：凡是「A 的取值随 B 变化」的常量，注释里必须写清 **A 换算成绝对量的当前值**
  （本项目现在写的是 `REASSERT_INTERVAL_SECS = 3`，并注明「以前是 tick 计数」）。

### 16.3 判据要有**宽容度**：要求「恰好相邻」的自检在真实桌面上必然失败

旧判据要求「我的正下方**正好**是桌面窗口」。听起来很准，实际上**桌面正上方那一格是公共地段**：
搜狗输入法常驻 **6 个隐藏助手窗**（`SoPY_Hint` / `SoPY_UI` / `Sogou_TSF_UI` / `IME` / `MSCTFIME UI`），
本应用**主窗**一显示也会挤进去。于是一个都没问题的情况被判成「错位」。

- **定规矩**：自检判据只问**用户真正在意的那件事**。用户在意的是「格子有没有压在桌面上面」，
  不是「我下面紧挨着的是谁」。⇒ 改成**有界下探**：往下走 N 层能碰到桌面就算对。
- **定规矩**：判据要能表达「**我判不了**」（本项目返回 `None` 就不动手）。
  「宁可不动，也不要基于一个存疑的判断去重排层层叠叠的 Z 序」。
- **定规矩**：判据**必须能被单元测试**。把「走链」抽成纯函数 `classify_chain(chain, host, hit_bottom)`，
  用假句柄测 —— 判据错了**不报错**，只会变成一个每秒重排的循环，代码里看不出异常，
  所以只有测试能钉住它。

### 16.4 任何自愈都**必须有保险丝**：上限 + 退避 + 只记一次日志

前面两条都做对了，也仍然要加保险丝 —— 因为**你不可能穷举真实环境**。
判据与现实万一还对不上，没有上限的重试就是无限重排。

- **定规矩**：周期性自愈一律三重保险：① 判据宽容；② 有**时间**间隔；③ **连续失败 N 次就退避 M 秒**
  （本项目 5 次 → 300 秒）。用户主动操作（隐藏→显示）时复位，让保险丝重新上膛。
- **定规矩**：退避本身要**只记一次日志**（用 `swap(false)` 这类原子位），否则日志刷屏会盖掉线索。

### 16.5 「看不见屏幕」时的窗口诊断法：把「消失」拆成**四种可判定**的成因

本项目最难的排查场景是**浮层窗口看似消失**。它「不见了」有四种完全不同的成因，
**肉眼看不出区别**，而 agent 会话看不到屏幕、本机 GUI 也起不来：

| 成因 | 窗口自己的表现 | 怎么问 |
| --- | --- | --- |
| 层级被顶到别的窗口上面 | `vis=True`，Z 序偏上 | 列 Z 序 |
| 被压在桌面**下面** | `vis=True`，排在 `Progman` 之后 | 列 Z 序 |
| 被最小化 / 隐藏 | `vis=False` 或 `iconic=True` | 列 Z 序 |
| **层级没问题，是前端没画内容** | `vis=True`、位置正确，但内容是空的 | `PrintWindow` |

工具已固化：**`scripts/audit/window-probe.py`**（子命令 `zlist` / `render` / `shot`）。

- **定规矩**：遇到「窗口不见了」，先跑 `zlist` 再跑 `render`，**把「层级」和「渲染」分开**。
  两者都正常 ⇒ 问题只能出在「反复重排」这类**动态行为**上，别再盯着静态属性看。
  （V36 就是这么定位的：层级对、渲染好，于是矛头直接指向那个循环。）
- 实现要点：`Progman` 是 Z 序最底；挂件窗应紧挨它上面（**中间可以夹窗口**）。
- 环境备注：本机 PowerShell 通道的 `Add-Type` 被安全层拦截 ⇒ 工具**不用 PowerShell**，
  纯 ctypes + 手写 PNG 编码（不装 PIL）。

### 16.6 右键菜单的关闭时机：用 `ref.contains(target)`，**不能只靠 `stopPropagation`**

菜单是 React 节点，而「点别处关闭」通常挂在 `window` 的**原生** `mousedown` 上。
React 的 `event.stopPropagation()` 只拦得住 React 自己的事件系统 —— **原生事件照样冒泡到 `window`**，
菜单会在点到自己菜单项的同一瞬间被关掉（表现为「点了没反应」）。

- **定规矩**：这类「点外面关闭」一律在 window 监听里判 `menuRef.current?.contains(event.target)`。
- 顺带：格子右键用 `event.clientX/clientY` 直接定位即可 —— 根容器是 `fixed inset-0`，
  和视口是同一套坐标，不必换算缩放比。

### 16.7 借鉴外部产品时：**先查「我们是不是早就有了，只是入口错」**

用户点名「借鉴腾讯桌面整理」的那些能力（重命名 / 新建 / 解散格子），本项目**早就都实现了** ——
问题一直是**入口**：要「先解锁布局、再找标题栏上的小按钮」，用户原话是「我都搞不懂」。

- **定规矩**：听到「别人家的 XX 功能」时，先 grep 自己有没有，再判断缺的是**能力**还是**入口**。
  缺入口就加**本能的入口**（右键菜单是桌面上最本能的动作），不要重写已有的能力。
- 同理：用户说「格子下左右都可以拉」，V35 其实已经补了 8 向缩放 —— 这类「要了已有的东西」
  要在回复里**点明已经支持**（并说明在什么模式下），否则用户会以为是新加的、也不会去试。

## 17. V37 确立的约定（破坏性默认值 · 用户文件的护栏 · 事故复盘的证据链）

### 17.1 「整理」这类词，默认含义 = **不动用户的文件**

用户对 V33–V36 的定性只有一句，但分量很重：

> 「是桌面整理，不是让你把桌面上的东西都给我移动到一个目录下面去，这个完全是错误的。」

- **定规矩**：凡是动词听起来无害的功能（整理 / 归类 / 收纳 / 优化 / 清理），**默认实现必须是非破坏性的**。
  「真的修改磁盘」这件事只能由用户**显式选择**触发，而且按钮文案要把后果说出来（「移动到…」而不是「整理」）。
- **推论**：允许保留破坏性能力（用户有时真需要归档），但要有三件套 ——
  ① 不是默认值；② 选择后有明显警示（我们是灰底说明 → 红底警示的切换）；③ 可逆（预览 + 二次确认 + 一键撤销）。
- **反面教材**：V33–V36 把「真移动」做成了唯一路径，还在确认框里写着「确定要整理吗」——
  用户根本无从知道「整理」=「搬走」。

### 17.2 会写用户磁盘的函数，入口必须有一句「我要动的就是这个目录吗」的自检

V36 那次事故的本质不是逻辑写错，而是**一个函数被喂了「目标在源内部」的参数**：

```rust
// 先建目标，再遍历源 —— 目标落在源内部时，遍历会看见刚建出的目标
fn copy_dir_recursive(src, dest) { create_dir_all(dest); for e in read_dir(src) { ... } }
```

- **定规矩**：任何 `rename` / `copy` / `delete` 的封装函数，**第一行**就要做「源与目标的关系自检」：
  同路径、目标是源的子路径 ⇒ 直接 `Err`。**不要**指望调用方永远传对。
- **定规矩**：兜底路径（rename 失败 → 复制+删源）比主路径危险得多，因为它会在**异常状态**下执行。
  写兜底逻辑时要问：「如果参数本来就是病态的，这条兜底会不会放大伤害？」——本案例是放大到 296 GB。
- **量级校准**：路径长度上限（32767 / `\?\`）、递归深度、条目数，都要有**显式上限**并报错返回，
  不能「让它跑到系统自己拒绝为止」。

### 17.3 复盘事故时：磁盘取证优先于读代码，且要**量化**

本轮能定案，靠的是三件事而不是猜：

| 证据 | 拿到什么 |
| --- | --- |
| 扫遗留目录（只读 `os.scandir` 显式栈） | 5 个目录 / 129,714 条目 / **296.03 GB** / 最深 **1001 层** / 最长路径 **7082 字符** |
| 路径形状 | `桌面\Handy整理\新格子 1\Handy整理\新格子 1\…` 重复约 1000 次 ⇒ 一眼看出是**自复制**而非「多跑几次各多一层」 |
| 真实数据库（`%APPDATA%\com.handy.desktop\handy.db`） | `grid_items` 里存的是 `…\Handy整理\新格子 3\诛仙世界.lnk` ⇒ 证明**登记指向收纳目录内部**，模型产物无疑 |

- **定规矩**：事故报告里不要写「大约很多」，要写**可复算的数字**（体积 / 条目 / 深度 / 最长路径），
  并保留取证脚本（本项目：`.tmp/v37/scan-legacy.py` → `legacy-scan.json`）。
- ⚠️ 读真实库**必须先连 `-wal` / `-shm` 一起拷出来**，否则读到的是过期快照
  （本轮 `handy.db` 12:16 落盘、`-wal` 14:06 才写完，只拷主库会漏掉最新状态）。
- ⚠️ 真实库在 `%APPDATA%\com.handy.desktop\`，**不在** `%LOCALAPPDATA%\Handy\`（后者只有 exe 与日志）。

### 17.4 「用户报错看不到日志」本身就是最该先修的缺陷

V33–V36 的日志只有窗口层级，**文件操作一个字都没有** ⇒ 事故无法从日志复盘，只能翻磁盘。

- **定规矩**：凡是会改用户数据的功能，**写入前先写日志**（源、目标、结果、失败原因）。
  日志要能在**产品界面里看到**（「诊断与修复」卡片可看尾部 / 打开目录 / 清空），
  因为用户不会去翻 `%LOCALAPPDATA%`。
- **定规矩**：前端也要接日志 —— `window.onerror` + `unhandledrejection` + React `ErrorBoundary`
  三条都要接，且上报函数**自身绝不能抛**（`void ... .catch(() => {})`），
  同一指纹去重（上限 200），否则一个渲染循环能把日志刷爆。

### 17.5 探针里的语义断言要有**反向**那一条

V33 把 smoke 探针从「不移动」改成守「真实收纳 / 真的移动」；V37 又反回来。
如果只写正向断言（新的词在不在），**旧词残留不会被发现**。

- **定规矩**：改产品语义时，探针除了断言新文案/新行为，**必须加一条「旧文案必须消失」**。
  本项目写法：`out.legacyHintGone = !after.includes('真实收纳') && !after.includes('真的移动')`。

## 18. V38 确立的约定（可见性 · 新建即可操作 · 例外的前提 · 布局可测 · 接管他人地盘）

### 18.1 「看不见」的东西等于不存在 —— 别为了干净把 UI 藏起来

V34 为了让桌面「清爽」，让**没有条目的收纳格不占位**；v9 迁移清空 `grid_items` 后，
用户桌面上所有格子同时满足这个条件 ⇒ **集体蒸发**，而管理页里一个都没少。
用户反馈是「动不动就不见了，**我找不到不见的规律到底是什么**」。

- **定规矩**：任何「空状态就隐藏」的过滤都要问一句 —— **用户能不能解释它为什么消失**？
  可发现性 > 视觉整洁。空格子要留在原位并写明「拖文件到这里」，空列表要写清「为什么是空的」。
- 同理，列表的 loading / 空 / 错误三态必须各自可辨，不能都用「什么都不显示」。

### 18.2 用户刚创建的东西，**必须处在可直接操作的状态**

`editMode` 默认锁定，`addBox` 建完不解锁 ⇒ 用户点了「+」，落出来的东西拖不动也改不了名。
「我新加的就是要操作的，你直接锁定了还怎么操作」—— 创建的意图本身就隐含了「我要编辑它」。

- **定规矩**：任何由用户显式创建的对象，创建后立刻进入**可操作状态**（必要时自动切换编辑态），
  并给一段视觉高亮告知它在哪儿（`focusNewBox`：解锁 + `interactive(true)` + 2.4s ring）。
  默认只读只适用于**用户没要求创建**的场景。

### 18.3 「跳过 / 不处理」的例外，**前提变了就必须重算**

V34 定「快捷方式留在原位、不参与归类」，前提是**原生桌面图标还在**（用户点得到）。
V38 改成接管桌面呈现后图标被隐藏，同一条规则就变成「桌上的程序快捷方式**没有入口可点**」。

- **定规矩**：每条「按设计跳过」的规则旁边，把**它依赖的前提写进注释**。
  改了前提（隐藏图标、换数据源、加了权限）之后，要回头把**依赖旧前提的例外**全扫一遍。
  本项目这次的反面教材：`.lnk` 例外只在 `icons stay visible` 下成立。

### 18.4 布局算法要有**可复算的单元测试**，否则「很乱」会反复回来

用户说「没有计算桌面合理的规划格子位置 流布局结构」——「合理」如果只存在于人脑里，
下次谁改排布参数都会把它改坏。V38 抽出 `FlowPlacer` 并配 7 条断言。

- **定规矩**：只要某个 UI 位置是**算出来的**（而非用户手工摆放），就要为它写纯函数级测试，
  断言必须覆盖：**起点 / 推进方向 / 边界（不许越界）/ 冲突（不许重叠）/ 穷尽（排不下要 None，不许叠压）**。
  且这类测试**不依赖平台 API**（这次刻意让它们在任何系统上都能跑）。
- 另外一个反复踩的点：**算排布必须同时拿到宽和高**。旧实现只有宽度，纵向一路排到桌面之外。

### 18.5 接管别人的地盘：要有**偏好记忆 + 立即归还 + 手动出口**三件事

隐藏系统桌面图标 = 接管 Explorer 的图标层。风险是「软件一关，桌面还是空的」。

- **定规矩**：做这类接管必须同时具备
  ① **偏好持久化**（`grid_meta.desktop_takeover`，与一次性的动作 `grid_desktop_icons_set` 分开记）；
  ② **收起 / 退出立刻归还**（`grid_overlay_hide` / RunEvent::Exit → `restore_desktop_icons`）；
  ③ **手动出口**（工具栏开关 + `grid_takeover_get` 回报真实可见性，失败要**如实提示**而不是假装成功）。
- 顺带：**被接管方本来提供的入口要自己补回来** —— 隐藏图标后此电脑/回收站/用户文件夹点不到，
  所以 V38 有 `ensure_system_box`（CLSID 虚拟条目，`::` 前缀豁免存在性校验）。

## 19. V39 确立的约定（对称性 · 静默降级 · 空隙复用 · 度量同源 · 表驱动 · 日志通道）

### 19.1 兜底必须**成对**出现：还回去了，就得有人负责收回来

用户反馈「源图标还在」，根因不是「隐藏失败」，而是**隐藏成功之后被一次瞬时不可见还原了，
而没有任何路径再收回来**。轮询线程里 `if !win.is_visible() { 归还图标 }` 是对的
（V30.1 的教训：最小化后桌面不该空着），缺的是对称的另一半。

- **定规矩**：写任何「失败退化 / 资源归还 / 状态回滚」的分支时，**同一段代码里必须回答
  「怎么回到正常态」**。若答案是「等下次用户手动操作」，那就不算自愈 —— 要么补周期自检
  （本项目：`reassert_takeover` 与 Z 序自检同节奏），要么在注释里写明为什么不需要。

### 19.2 **静默降级 = 伪装成功**，布局算法尤其不能有

V38 的排布器排不下时 `stuck += 1; continue;`（保持原有坐标），日志还写得很体面：
`重排格子：挪动 4 个……4 个没地方放（保持原位）`。用户看到的是**格子散落在桌面各处**，
而程序认为自己「整理完成了」。

- **定规矩**：布局 / 批量操作里出现「放不下 / 做不了」时，只允许三种收场：
  ① **降级重试**（缩到最小尺寸再来一次）；② **兜底安置**（`place_loose`：宁可压在一起，
  也要留在同一个区域里、顺序不乱）；③ **明确报错**。**绝不允许「保持原样 + 当作成功返回」**。
  而且要把降级次数作为**报告字段**交给 UI（`boxesOverflowed`），让用户能看见。

### 19.3 排布器的空闲区必须能**复用**（游标只增不减是错的）

V38 的列内游标 `cursor_y` 单调递增：大格子 / 挂件在一列里切出来的空隙**再也用不上**。
格子尺寸一旦按内容量变得参差，这个缺陷立刻放大成大片浪费 + 后面的格子排不下。

- **定规矩**：打包 / 排布用**首次适配**，且候选位置只取「容器顶部」与「每个相交矩形的下沿 + 间隙」
  这两类点（最优解必在其中），升序试第一个放得下的即可 —— 不必按像素扫描。
- 列宽要**统一**（取本批最宽），列数**按容器宽度推导**，别写死。

### 19.4 尺寸算法必须与**渲染度量同源**，且写明耦合点

`auto_box_size` 里的 `iconSize + 36 × iconSize + 30` 直接对应前端
`gridTemplateColumns: repeat(auto-fill, minmax(iconSize + 36px, 1fr))` 与单元格的
`p-1.5 + gap-1 + 11px 文字`。

- **定规矩**：凡是「按内容算容器尺寸」这种跨语言耦合，必须在**两侧都写清「另一侧在哪」**，
  并列出每个数字的来历（padding / gap / 行高）。这类耦合**不会**被 tsc、cargo 任何一层拦住。

### 19.5 位置这类「策略」要**表驱动**，不要散在代码里

用户说「日历默认放右上角等，以后我们可能还会增加更多小挂件都可以固定位置」。
于是有了 `widget_corner(kind) -> WidgetCorner` 一张表 + 通用 `anchor_widget(角落, 已占, …)`。

- **定规矩**：新增一类东西（挂件 / 面板 / 工具分类）时，先问「能不能只往表里加一行」。
  表里没登记的 kind 也必须有**确定**的兜底位置（不能留在旧坐标上乱飘）。
- 同角落多个实例必须**竖排且夹回可视区**（堆太多时算出来的 y 会变成负数 → 用户以为「挂件丢了」）。

### 19.6 日志通道只能有一个，`println!` 是复盘盲区

V38 的 `release_icons_if_taken` 用 `println!` 输出「自动恢复系统桌面图标」——
**只进控制台、不写 handy.log**。于是「图标被谁还回去了」这件事在用户回传的日志里根本不存在，
排查「源图标还在」时多绕了一大圈。

- **定规矩**：后台线程 / 兜底路径里的诊断信息一律走 `grid_log`（→ `handy.log`）。
  只有「给人看的启动横幅」才允许 `println!`。**判断标准：这条信息在事故复盘时有用吗？**

### 19.7 测试里的上限 / 阈值必须与**生产调用同源**

给 `auto_box_size` 加测试时，测试按 `work_h - 2*margin` 自己算了一遍高度上限，
而生产调用传的是另一个量 → 出现「函数没错、测试写错」的假失败（正是 §6 说的
「回归里算错的期望值比产品代码更危险」）。

- **定规矩**：测试里不要重复推导生产侧的参数，**直接引用同一个常量/同一个表达式**，
  并在旁边写一句为什么（本项目：测试里的 `MAX_H` 与 `layout_all_boxes` 传的是同一个量）。

## 20. V40 确立的约定（触发条件 · 视觉判据 · 前提失效 · 观察窗 · 测试可读性）

### 20.1 触发条件必须挂在「用户的意图」上，不能挂在「本次做了什么」上

用户 V40 第①条「桌面原图标还存在呢」的真根因，是一行看起来很有道理的条件：

```rust
if report.items_added > 0 { takeover_icons(true) }   // 本意：空跑一次别顺手藏人家图标
```

问题在于「这次没登记新条目」**不等于**「用户没在要求整理」：用户的桌面早就全部登记过了，
此后每一次点「整理桌面」拿到的都是「登记 0 项」⇒ **接管这个动作永远不会发生**。
V39 刚加的 `reassert_takeover` 也救不了它 —— 自检只在「偏好本来就是开」时才跑，
而这个偏好**从没被打开过**。两层逻辑各自都对，叠起来就是功能整体不存在。

- **定规矩**：写 `if (本次的变化量 > 0) { 执行用户明显期待的动作 }` 之前先问一句
  **「这个条件在稳态（用户已经整理好一遍之后）还成立吗？」** 稳态下不成立的条件，
  只能用来控制**程度**（比如「这次登记了几项」），不能用来控制**是否执行**。
- 真正需要保留的那道闸是**安全性**检查（「挂件层没在显示时不许藏图标」，否则桌面会空白），
  它与「本次做了多少事」无关 —— **安全条件与行为条件要分开写**，别用一个布尔值兼职两件事。

### 20.2 「对齐」这类视觉要求要落到**可断言的几何**上

用户说的是「宽度对齐，整理排列，流布局」。这句话翻成代码只有三个判据：
**列宽只有一种**、**列位置落在等距网格上**（`(x - margin) % (列宽 + 间距) == 0`）、**全部两两不重叠**。
V39 只做了「高度按内容」，宽度仍由每格自己按「尽量方形」推 ⇒ 真实库里出现 160 / 228 / 300
三种宽度，左边缘参差，用户看到的还是乱。

- **定规矩**：凡是用户用「整齐 / 对齐 / 匀称」描述的需求，**先写出几何断言，再写实现**，
  并把这些断言放进测试（本项目：`one_standard_width_for_the_whole_batch` /
  `every_column_sits_on_the_same_pitch` / `a_full_pass_never_overlaps`）。
- 起点方向也要**明确**并写进测试名：本产品是**左起**（桌面图标本来就从左上角排起），
  右上角留给日历、左下角留给便签 —— 方向一变，整套断言都得跟着改，所以必须有测试钉住。

### 20.3 高度随内容撑开的前提是**列宽统一**

`box_height_at(items, w, icon, max_h)` 里，行数是 `w` 的函数。只要每个格子用**自己的**宽度，
就会出现「小格子因为窄而更高」这类反直觉结果，用户看到的就是「高低乱七八糟」。
先把列宽统一，再谈高度 —— **顺序反了，高度算得再准也没用**。

### 20.4 「桌面」从来不是一个目录

`dirs::desktop_dir()` 只给出 `%USERPROFILE%\Desktop`，而 Windows 桌面是
**用户桌面 + `%PUBLIC%\Desktop` 合并显示**的。公共桌面里有 15 个「所有用户」快捷方式
（微信 / QQ / Chrome / PyCharm / ToDesk / 钉钉…），只扫一个目录 ⇒ 它们永远不进格子，
用户看到的就是「那么多文件文件夹都没有整理好」。

- **定规矩**：凡是「枚举用户可见的 X」的地方，先确认 X 在系统层面是否**由多个位置合成**
  （桌面 / 开始菜单 / 字体 / 环境变量都属此类）。合成来源要一起扫，且**单个来源失败不能中断整体**
  （只记进 `failures`）。
- 判断「取不到的来源」时返回 `None` 而**不是**报错（非 Windows / 精简系统属正常情形）。

### 20.5 例外的前提一旦消失，例外必须**同时删掉**

V38–V39 会跳过桌面上的历史容器 `Handy整理*`（理由是「自己的收纳容器永不参与，V36 事故根源」）。
但那次事故的成因是 `fs::rename` + 递归复制兜底，而 V37 起整理**一个字节都不移动** ——
前提早就不存在了，跳过却留了下来，于是桌面上永远有几个文件夹不在任何格子里。

- **定规矩**：写「跳过 / 忽略 / 特殊对待」时，注释里必须写清**它依赖的前提**；
  那个前提被推翻时，**回到原处把例外删掉**。同时报告字段（`skipped`）的语义要一并更新并注明
  （本项目：V40 起 `skipped` **恒为 0**，字段保留只为前后端契约稳定）。

### 20.6 给「看起来坏了」的状态留一个观察窗，别急着回滚

挂件层不可见有两种：**瞬态**（Win+D / 「显示桌面」/ Explorer 重建，几十毫秒）与**终结态**
（用户收起挂件 / 退出应用）。V38–V39 一视同仁地立刻归还图标 ⇒ 每次 Win+D 都还回去一次。

- **定规矩**：对「可能只是抖动」的信号，不要二值判断，要**加时间宽限**
  （本项目 `OVERLAY_AWAY_GRACE_SECS = 30`）；而**明确的用户动作路径**（收起 / 退出）
  仍然走**立即**执行。宽限期内状态**升回正常时立刻纠正**（回来时马上自检，不等下一个周期）——
  宽限期只该放宽「判死」，不该放宽「复活」。

### 20.7 测试里的元组列序写错，编译器**不会**吭声

端到端预演测试里 `read_boxes` 返回 `(kind, x, y, w, h, items)`，断言却当成 `(name, ...)` 用 ——
`"快捷方式"` 与 `"folder"` 都是 `String`，类型完全合法，只在运行期炸出「找不到格子」，
报错位置离真问题很远。同一份测试里还犯了第二次：拿 `kind` 的值（`"calendar"`）去比 `name`
（库里是用户改过的中文「日历 · 今日计划」）。

- **定规矩**：测试里**超过 3 列的数据一律用具名字段结构体**（`struct BoxRow { name, kind, x, y, w, h, items }`），
  从类型上根除「列序想当然」。按什么字段查也要在断言旁边写明（「库里名字是中文，锚点由 kind 决定」）。

### 20.8 单测不许往用户真实日志里写东西

`cargo test --lib` 会跑到 `logging::write_line` ⇒ 往 `%LOCALAPPDATA%\Handy\handy.log` 里
插进几十行假的「整理布局 / 接管图标」记录。**那条日志是事故复盘的事实源**，
掺进假记录会让下一次排查被误导（比「没有日志」更糟）。

- **定规矩**：写文件的日志 / 遥测通道，在 `cfg!(test)` 下**直接返回**；
  测试只断言返回值，不断言副作用。任何「会写用户目录」的代码都要问一句「测试跑它安全吗」。

## 21. V40.1 确立的约定（Tauri dialog 插件会把 `window.confirm` 换成 async + 缺 ACL ⇒ 破坏性操作静默执行）

`@tauri-apps/plugin-dialog` 注入 webview 后，会把原生 `window.confirm` / `window.alert`
整体**重写**成 async 的 IPC 调用（`plugin:dialog|confirm` / `plugin:dialog|message`）。
这带来一条**看不见、四层门全拦不住**的缺陷：

- **① 权限缺口**：`dialog:default` 权限集只含 `allow-message` / `allow-save` / `allow-open`，
  **没有 `allow-confirm`** ⇒ 调用必然 reject，日志里表现是
  `未处理的 Promise 拒绝：Command plugin:dialog|confirm not allowed by ACL`。
- **② 语义错配**：它变成 async 之后，老写法 `if (!window.confirm(...)) return;`
  拿到的其实是 **Promise 对象（`!Promise` 恒为 false）** ⇒ **删除格子 / 删除备份 /
  还原布局这些破坏性操作直接执行，用户根本没被问过**。`if (!ok)`（`ok` 是 Promise）同理。
- **③ 为什么拦不住**：`tsc` / `cargo` / 回归 / 冒烟四层全在浏览器或纯逻辑环境跑，
  而浏览器里 `window.confirm` 本来就是**同步 boolean**，测试环境永远正常 ⇒ 只有**用户真机启动**才会暴露。

**修法（已落地）**：
- 前端一律走 `src/lib/confirmAction.ts` 的 `confirmAction(msg)` —— 内部 `await window.confirm`，
  **任何异常保守返回 `false`**（问不到就不做，破坏性操作绝不因「问不出来」而默认执行）；
  所有调用点必须是 `async` 且 `if (!(await confirmAction(...)))`。
- `src-tauri/capabilities/default.json` 的 `permissions` 必须补 `"dialog:allow-confirm"`
  （不补，① 的 reject 就会一直生效，确认框永远弹不出来）。
- **定规矩**：Tauri 前端**禁止直接写 `window.confirm`**，破坏性确认只能走 `confirmAction`；
  新增任何 dialog 类权限时，默认把对应 `allow-*` 一并写进 capability，不要想当然以为
  `dialog:default` 已经够用。

### 21.1 Z 序自检在「繁忙桌面」上仍可能误判 —— 用「沉底再上提」兜底，并把失败暴露出来

V40.1 真机启动还抓到第二条：`Z 序自动纠正已连续失败 5 次，暂停 300 秒`
（V36 立的保险丝，本意是判据与本机不符时别一直闪）。根因仍没 100% 坐实，但两处加固：
- `place_above_desktop` 从单步 `SetWindowPos(hwnd, host)` 改成**两步**：先 `SetWindowPos(hwnd, HWND_BOTTOM)`
  沉到 Z 序最底，再 `SetWindowPos(hwnd, host)` 贴回桌面宿主之上 —— 单步在某些本机
  （桌面宿主被 Explorer / 第三方桌面工具反复重排）会「贴不进去」，窗口仍停高位 ⇒ 自检永远判
  `TooHigh`、保险丝反复熔断。先沉底再上提强制刷新插入点，比单步稳。
- `reassert_attach` 里原本 `let _ = place_above_desktop(hwnd)` **吞掉了错误** ⇒ 贴失败也看不到原因。
  改成 `if let Err(err) = place_above_desktop(hwnd) { grid_log(...) }` —— 下次真机日志能直接看到
  `重新贴回桌面层失败：...`，据此区分「贴不进去」还是「判据本身错」。
- **定规矩**：凡是有副作用、会失败又容易被 `let _ =` 吞掉的诊断/纠正动作，都要把失败**落日志**；
  自愈类保险丝的 log 文案要带「请把这行发我」式的引导，让真机日志成为排查入口。
  （`REASSERT_SCAN_STEPS = 24` 暂未调大：它只在「窗口真被顶得很高」时才有意义，
  调大反而会掩盖真实 `TooHigh`，等真机日志确认贴失败再决定是否调。）



## 22. V41 确立的约定（右键跟对象走 · 移出要有去处 · 挂件竖排的让位顺序 · 机器相关测试要注入）

- **右键菜单跟「被点的对象」走，不跟「容器」走**：格子菜单曾挂在整个 `<section>` 上，

- **「移出」必须有去处**：接管模式下移出格子 = 条目进「没登记、原生图标又被隐藏」的真空态，

  都由挂件层画在左下角（可见 / 可开 / 可拖回）。**定规矩**：呈现层模型里，每条「从 A 状态移出」
  的路径都必须回答「它接下来显示在哪」；答不上来就是下一个投诉。
- **「不整理」区只在接管模式下渲染**：接管关着时这些图标桌面上本来就有，再画一份就是两份
  （V38 的教训「桌面出现两份相同内容」换个方向又会出现）。
- **挂件竖排（同角落多挂件）的让位顺序 = 先底部边距、再重叠**：912 高的工作区里
  日历 638 + 便签 220 按老钳制（保留底部边距）会互叠 10px。挂件压挂件比挂件贴住屏幕下沿
  难看得多 ⇒ `clamp_y` 放宽到 `work_h - h`。**定规矩**：「宁可 X 也不 Y」式的兜底排序
  要按视觉伤害排序，且要有测试真把「放不下」的场景灌进去（这次就是端到端预演抓到的）。
- **端到端测试不得依赖跑测试那台机器的桌面**：`layout_all_boxes` 内部扫真实桌面数「落单条目」，
  测试机上用户桌面全是未登记 ⇒ 算出巨型不整理区堵死固定列，断言全盘崩。修法 =
  `layout_all_boxes_with(loose_count)` 注入版本，测试传 0。**定规矩**：凡是「读真实用户环境」
  的输入（桌面、注册表、真库），进布局/决策函数前要能被注入替换。
- **同文件多处 Edit 并行发（即便在不同消息里连续发）也可能竞争丢改动**：本轮一对并行 Edit
  「成功」了一条丢了另一条，编译期才炸出来。铁律（坑 1）再确认：同一文件的编辑**串行**。

## 23. V42 确立的约定（左条不是格子 · 镜像流布 · 功能下沉到桌面 · 侧栏用开关而不是删模块）

- **「不参与整理」的东西不要给它造格子**：V41 把系统图标 / 快捷方式做成「左上固定列」的两个格子，
  用户 V42 原话「不整理的和快捷方式别整理到格子了，他们就是自动在桌面左上角从上往下排开即可，
  没有必要」。改成**左侧「未归类」竖条**（`loose_strip_rect`，纯图标、无卡片外壳、无标题），
  系统图标 → 快捷方式 → 落单文件（`loose_rank`）依次排，N 列 × N 行。**定规矩**：区分「容器」和
  「清单」——凡是被整理的东西才配拥有格子；只是要看得见的东西用条/列表呈现，别套格子语义。
- **自动整理要能撤销上一次的分类结果**（`dissolve_auto_boxes`）：用户要求「每次点击整理桌面，
  应该重新计算桌面所有的内容」。若只是增量登记，上一次被误收进格子的 `.lnk` / 系统条目会一直留在
  里面（V42 就是从 V41 的存量数据上暴露的）。修法 = 每次自动整理前先
  `DELETE FROM grid_items WHERE file_path LIKE '::%' OR lower(file_path) LIKE '%.lnk'` +
  `DELETE FROM grid_boxes WHERE kind='system' OR name='快捷方式' OR category='快捷方式'`，
  再由 `arrange_group_of` 对 `.lnk` 返回 `None`（永不进格）。**定规矩**：「一键整理」类动作必须先清
  自己上一次的产物再重算，幂等 = 可重复执行且结果一致；写这类 DELETE 时要顺手给出
  `dissolved_boxes/items` 计数，让报告能自证。
- **镜像流布（`FlowPlacer::mirror`）**：用户要「右边是从挂件到其他整理，从右上角依次顺序排开」。
  实现 = 第 0 列是最右列、列号从右往左递增，`min_x` 作为左边界为左侧竖条留地。
  两个坑：① 首列起点要按 `work_w - margin - col_w` 算，不是 `margin`；② **first-fit 会回填空档**
  ——后面的小格子会插进前面大格子留下的空隙，偏移量因此**非单调**。写断言时别断言「左到右单调」，
  要断言「至少有一个格子贴到最右可用列」+「首格从右侧起」；另外被钉住的挂件（日历）右上角下方
  也可能塞进矮格子，「格子必须在挂件左边或正下方」这类断言在镜像模式下不成立。
- **主窗口侧栏用 `sidebar: false` 开关隐藏模块，不要删模块**：用户要「工具主页面里面就只需要保留
  工具箱和密码存储器」，但桌面整理 / 工作台的**命令**仍要能被搜索到。于是给 `ModuleMeta` 加
  `sidebar?: boolean`（默认 true），侧栏 `registry.enabled().filter(m => m.sidebar !== false)`。
  **定规矩**：「从导航里拿掉」和「从产品里拿掉」是两件事，前者改展示层开关，后者才动注册。
- **桌面层要能直接打开工具**：新增 `desktop_open_view(app, target)` —— 走 `handy:navigate`
  事件（与 `bar_open_command` 同一套机制）把 target 发给主窗口，不新开窗口。
  桌面搜索面板直接复用 `registry.commands()` / `searchCommands`，搜到即 `openTarget`。
  **定规矩**：新增「从 X 处打开 Y」的入口时，先看已有导航事件能不能复用，别再造一个窗口。
- **桌面 Dock 与工作台快捷方式共用一份数据**（`workstation/quicklinks.ts` 的 localStorage），
  两边都读写同一 key ⇒ 在一边加的快捷方式另一边立刻可见。**定规矩**：同一份用户数据在两个
  呈现层出现时，抽出单一数据源模块，别各存一份再同步。
- **拖放落点判定要按 z 序/优先级依次命中**（Dock → 格子 → 落单条 → 空白），且先做类型收窄：
  `payload.type === 'leave'` 先 `return`，再访问 `payload.position`，否则 TS 报属性不存在。
  **定规矩**：一个 drop 有多个候选落点时，显式写出命中顺序，不要靠 DOM 层叠顺序隐式决定。

## 24. V43 确立的约定（只增不减的名单是定时炸弹 · 拖放的两个 effect 必须兼容 · 接管了桌面就要替 Shell 弹菜单 · 能在现场开就在现场开）

- **「只增不减的黑名单」是定时炸弹**：`sync_dismissed` 的初衷是「用户移出的东西别被下一次整理
  拉回来」，但它是单向累积的 —— 用户手动挪出去过的目录 / 文件此后**永远**不会再被整理，
  而界面上没有任何地方能看出这件事。真机库实测攒了 13 条（`_Work` / `software` / `测试` /
  `dify` / `1.log` / `skills.tar.gz` / 两个 pdf…），用户看到的就是「我重新整理了为什么还是
  没有重新整理」。日志自证的形态：`扫到 72 项，登记 0 项，未归类留在左侧竖条 39 项`。
  **定规矩**：任何「记住用户否定过什么」的持久状态，（a）必须有一个**显式的重置入口** ——
  这里就是「一键整理」前先清空（用户点整理 = 要求按现状重算，此时尊重现状而不是尊重历史）；
  （b）必须在动作日志与 UI 提示里**报出放开了几条**（`released`），否则用户无法分辨
  「没东西可整理」与「被名单拦住了」。
- **HTML5 拖放的 `effectAllowed` 与 `dropEffect` 必须兼容，否则表现为「拖不进去」**：
  拖动源写 `effectAllowed = 'move'`、落点写 `dropEffect = 'copy'`，浏览器直接判定禁止放置，
  **连 `drop` 事件都不会触发**（日志里什么都看不到，最难查）。
  一个拖动源有多个语义不同的落点时要写 `copyMove`（拖进格子 = 移动归属；拖到快捷条 = 收一条
  快捷方式）。**定规矩**：落点声明 `dropEffect` 之前，先回头看拖动源的 `effectAllowed` 集合。
  另外 `onDragOver` 里判「能不能落」时，除了看 ref（同窗口拖动），也要看
  `dataTransfer.types` 里的自有标记 —— 拖拽被中断过、ref 已清空时仍要能落。
- **接管了原生桌面，就要替 Shell 把它的菜单弹出来**：接管模式下原生图标（`SysListView32`）
  被隐藏，右键落到了我们的窗口上；只弹自己的小菜单 = 打开方式 / 发送到 / 复制 / 删除 / 重命名 /
  属性 + 第三方 shell 扩展全部消失（用户原话「你的格子把我图标原始的右键功能全部覆盖了，
  这个科学吗」）。腾讯桌面整理的做法就是**格子里图标右键 = 系统原生菜单**。
  **定规矩**：凡是「替系统显示某个对象」的功能层，都必须同时替系统提供**该对象的原生操作入口**
  （右键菜单是最低要求）；自己那套菜单只能作为补充，且要放在一个明确的次要入口后面（这里用 Shift）。
  实现见 `platform/shell_menu.rs`：`SHCreateItemFromParsingName` → `BindToHandler(BHID_SFUIObject)`
  → `QueryContextMenu` → `TrackPopupMenuEx(TPM_RETURNCMD)` → `InvokeCommand`；
  **必须经 `run_on_main_thread`（`TrackPopupMenuEx` 自己跑模态消息循环）**，
  弹完补一条 `PostMessage(WM_NULL)` 否则菜单会「粘」在屏幕上。
- **「能在现场开，就在现场开」—— 别把用户赶到另一个窗口**：用户原话「我在桌面上就能完成
  所有的操作 不需要调出一个窗口去找工具等」。工具 / 模块的 UI 本来就是**同一份组件**
  （`CommandMeta.load()` / `ModuleMeta.loadView()`），换个宿主就能在桌面抽屉里渲染，
  不需要为此复制一套界面。**定规矩**：新增「从 A 处打开 B」的需求时，先问「B 的组件能不能
  直接挂到 A 的现场」；能挂就挂，挂不了（动作式命令没有界面）才退回「唤出主窗口 + 导航」。
  推论：主窗口的角色要跟着变 —— 它从「日常入口」退化成「设置 / 管理控制台」，这是**收益**
  而不是妥协，不要在文档里把它继续描述成主入口。
- **同一份用户数据出现在两处呈现层时，抽单一数据源**：桌面 Dock 的系统快捷入口与工作台的
  快捷入口栏共用 `settings.quickActionIds` 与 `ACTION_ICONS`（后者从 QuickActionsRail 导出）。
  在两处各存一份 = 迟早不一致，而且用户会认为「我在这边删了那边怎么还在」。
- **把「摆放顺序」和「格子顺序」解耦**：挂件占掉右上角后，最右两列的可用顶端会被压到挂件下沿，
  高格子塞不进那道缝、只能挤走，右侧就留下「一列一格」的碎片（用户：「经过整理后的桌面其实
  还是乱的 都没有对齐」）。让**条目少的先摆**能把这些碎片位填满。
  **定规矩**：改动「谁先摆」之后，凡是断言「第 N 个格子必须在第 M 列」的测试都会失效 ——
  那类断言绑的是摆放顺序而不是布局规则，要改断言而不是改回顺序（见 V43 对
  `real_desktop_data_lays_out_in_aligned_columns` 的修正）。

  `PasswordGenerator.ResultBox` 用了 `Tooltip`，工具在桌面抽屉里一点开就抛
  `Tooltip must be used within TooltipProvider` 白屏（用户日志抓到）。修法不是给每个工具加
  Provider（一定会漏），而是**在 `main.tsx` 的 `ErrorBoundary` 外层统一包一层**覆盖所有窗口根。
  以后再给工具加「依赖某个 Provider / Context / 全局 CSS 变量」的能力时，先自问：挂件窗里谁来提供？

- **面板要收敛，不要堆叠**：V43 的 `DesktopToolPanel` + V44 的 `DesktopQuickActions` 是两次
  独立加面板，结果桌面上同时存在「搜索浮层 / 工具箱抽屉 / 快捷浮层」三套观感不一的 UI，
  用户原话「还是有点混乱了」。V45 合并为一个 `DesktopSidePanel`：同一外壳、同一位置（右侧滑入）、
  顶部搜索框 + tab 切换，工具本体**就地渲染**。**加第三个面板前先想能不能做成 tab。**
  右侧要留 `right-[124px]` 给常驻工具栏，否则面板会盖住「关掉面板」的按钮本身。

- **壳与内容分离**：「密码存储器并入工具箱」只动注册（删 `modules/vault/index.ts` +
  `toolbox/commands` 加一条），`VaultView.tsx` 与 Rust 侧加解密**一个字没改**。
  想「合并 / 迁移模块」时优先找这种**零成本搬迁**的切法，不要顺手重写业务实现。
  工具壳里**不要再套 `CommandShell`**（`VaultView` 自带标题栏，套了就是双标题栏）。

- **接管期间装机 = 必须先归还桌面**（本轮踩到，重要）：除了 `hide` / `--show-grid`，
  **没有第三条路**能让被藏起来的 `SysListView32` 回来，而装机必须停旧版进程。若应用正处于接管态
  （`grid_meta.overlay_visible=1` + `desktop_takeover=1` + `desktop_icons_hidden=1`），
  `Stop-Process -Force` **不会**触发 `RunEvent::ExitRequested`（那是 `app.exit()` 才走的优雅路径），
  桌面就空着。装机固定流程：
  1. 先查 DB 确认是否接管态；
  2. `Stop-Process -Force` 停旧版；
  3. **立刻** `python scripts/audit/desktop-icon-restore.py`（ctypes 调 `ShowWindow(SW_SHOW)`）+ 用
     `scripts/audit/desktop-icon-probe.py` 复核；
  4. 把 `grid_meta.desktop_icons_hidden` 改回 `'0'`（否则下次启动 `heal_desktop_icons` 白跑一次）；
  5. 再 PowerShell `Start-Process -ArgumentList "/S" -PassThru -Wait` 静默装机；
  6. `cmp -l` 取证（只应差 3 字节）。
  ⚠️ **顺序不能反**：先恢复图标再杀进程是错的 —— 接管自愈会在 3 秒内把图标**重新藏起来**。
  ⚠️ 别用 PowerShell `Add-Type` 调 `user32`（本机安全策略直接拦 `Add-Type`：Command blocked for
  security），用 Python `ctypes`（Python 侧无此限制，`desktop-icon-probe.py` 就是这么写的）。

- **审计脚本别去解析「人写的格式」**：`tool-audit.mjs` 用 `export type ToolCategory = ([^;]+);`
  读联合类型；我把等号后写成换行，它就解析不到，于是「分类图标登记」整批断言**静默失效**（不是失败，
  是通过）。改成 `=\s*([^;]+);`。凡是靠正则读源码来断言的检查，**格式一变就可能静默变弱**；
  写这种解析时加一条「解析结果为空 → 直接 FAIL」的守卫，别让空集合恰好通过。

## §27 V46 确立的约定（窗口 Z 序 API 的方向 · 判据对了才有自愈 · 收起态不许动图标 · 桌面上的东西一律不透明）

- **`SetWindowPos` 的 `hWndInsertAfter` 是「排在我前面（更靠上）的那个」⇒ 我被放到它下面**。
  V12–V45 的 `place_above_desktop` 写的是「先 `HWND_BOTTOM` 沉底，再 `SetWindowPos(hwnd, host)`
  贴到桌面宿主之上」，**方向正好说反了**：第二步实际是「放到桌面宿主**之下**」。
  之所以一直没炸：用户机 `desktop_host()` 命中的是 `Progman`（Z 序最底），
  「普通窗口不可能低于桌面」被系统钳制，落回同一位置，侥幸成立。
  换一台机器（`desktop_host()` 走「顶层 WorkerW」那条分支）就会把挂件层推到
  **原生图标背后** —— 用户看到「整理好的桌面整个不见了」。
  ⇒ **约定：要「贴在桌面正上方」就只调一次 `SetWindowPos(hwnd, HWND_BOTTOM, …)`。**
  它是幂等的、可反复调用的，且 Windows 保证普通窗口不会低到桌面之下。
  ⚠️ 用 `scripts/audit/zorder-probe.py` 现场验证，别凭 MSDN 的中文翻译推理 ——
  这条注释在仓库里错了 30+ 个批次。

- **判定对了，自愈才有意义；判定错了，自愈就是伤害**。V46 之前 Z 序守卫的形态是
  「连续两次判定不对才纠正 + 3 秒间隔 + 连续 5 次后退避 300 秒」。真机实测：单次会话
  **265 条** `TooHigh` 日志、8 条 `BelowDesktop`，用户看到的是「桌面消失好几分钟」。
  ⇒ 约定：**恢复延迟是产品指标，不是调参**。桌面层保险的目标是「用户察觉不到」：
  检测 ≤1 秒、判到就纠（动作幂等才敢这么干）、退避上限 5 秒。
  这三条已写成单测 `band_insurance_recovers_fast`，改之前先读 `DESKTOP-LAYER §2.4`。

- **「收起」是一个状态，不是「少做一件事」**：`grid_overlay_hide` 交还了图标，
  但 `reassert_takeover` 只看「接管偏好」不看 `overlay_visible`，3 秒后又把图标藏回去
  ⇒ 用户面对一个**空桌面**（格子内容收起 + 图标也被藏）。
  ⇒ 约定：任何「自愈 / 纠偏」路径动手前，**先读唯一真源**。
  见 `DESKTOP-LAYER` 不变量 I1：`Off ⇒ 原生图标可见`。
  更普遍的形态：**一个自愈动作的如果条件，必须包含「它要修的那个状态仍然成立」**。

- **显示态却不可见，必须有路把它捞回来**：此前挂件层「不可见」只有「图标归还」的兜底，
  **没有路径重新 `show()`** —— 用户只能去托盘瞎点（实测原话：「我到托盘里面点了下 handy，
  然后最小化 handy，桌面才又出来」）。⇒ 约定：**每一种「不该发生但可能发生」的窗口状态，
  都要有一条自动恢复路径**；只做「止损」（归还图标）不做「恢复」（重新显示）等于把用户扔在原地。

- **日志限流不能把「第一次」也吃掉**：V45 单次会话 265 行同类日志 ⇒ 真出事时日志被淹；
  但简单地把重复日志删掉，又会失去「第一次故障」的证据。
  ⇒ 约定：**每轮突发留第一条 + 全局最小间隔**（`fixes == 1 && 距上条 ≥ 60s`），
  并且第一条要**带上定位信息**（V46 新增 `z_chain_brief()`：往下走的前 4 个窗口类名）。
  「刷屏」和「查不到」是一对反方向的失败，限流策略要同时堵住两边。

- **桌面上的东西一律不透明**（用户 09-19 明确要求：「工具箱这些工具类不要透明了，
  透明有问题」「现在这个全都是透明很难清楚的操作」）。
  ⇒ 约定：挂件层里的**面板 / 工具本体 / 工具栏 / Dock** 用实心
  （`bg-neutral-900` / `bg-neutral-950`，靠 1px `ring` 与阴影分层次），
  不用 `/NN + backdrop-blur` 那套玻璃。半透明在桌面上是**可用性缺陷**：
  壁纸是照片时正文、次级按钮、分隔线全糊在一起。**格子本体**保留玻璃质感
  （那是呈现层的一部分，与壁纸的融合是刻意的）。

- **面板的定位要按「对方现在的尺寸」算，不能按记忆里的尺寸算**：
  `SIDE_PANEL_SHELL` 的 `right-[124px]` 是按「工具栏约 92px 宽」估的；
  V45 给工具栏加了「密码箱」按钮，工具栏宽到约 236px，于是面板把工具栏盖住了
  （用户截图里「工具栏不见了」的观感来源之一）。
  ⇒ 约定：**写死像素避让时，把「被避让方的实际宽度」写进注释**，
  并把它当作「改动那个组件时要一起更新的东西」。
