## 0. 一句话现状

**Phase 1（MVP）功能已全部交付，并完成六轮用户自测反馈大修（V18–V23）**：命令面板统一入口 + 工具箱 **25 个工具** + **桌面网格挂件（V21 起以顶层窗贴在桌面之上，透明可点）** + **桌面整理主控台** + **工作台（日历含农历/节气/节假日/纪念日 · 计划 · 便签所见即所得 · 自适应竖排快捷入口）** + **桌面顶部贴条（可展开折叠、置顶可关）** + 密码存储器；**Windows 安装包已重新产出（V23）**；`cargo check`、`tsc`、回归全绿。V23 做的是**「去掉重复、标清边界、补齐文本处理能力、并用实测代替肉眼」**：合并 Cron 工具里重复的「字段拆解」面板并给 Quartz 语法标上适用平台与误用警示、新增 **文本处理台**（查找替换/正则筛选/20 项行操作/取列/统计）、把「响应式布局」从口头要求变成**可复跑的自动审计**（`scripts/audit/layout-audit.mjs`，实测抓出并修掉工作台在窄窗口下「日历被裁两周 + 计划面板被压成 19px 空壳」两处真缺陷）。

**V24 做的是「把界面做现代、把工具做成能无限扩展的」**：设计令牌升级（页面底色 `--canvas` 与纯白卡片拉开层次、圆角/阴影/动效统一）、工具箱**分类体系与首页重做**（搜索 + 分类页签 + 收藏/最近 + 按分类分组）、**19 个工具接上状态持久化 + 8 个工具补示例条**，并把「加工具容易漏配」做成**脚手架 + 静态自检 + 编写指南**三件套 —— 首次运行自检即抓到 **3 个工具的图标从未登记**（一直静默显示扳手）。

**V25 做的是「把三条用户实测的不合格项修到根上，并把自测推进到端到端」**：① 密码生成器**符号占比默认从 100% 降到 25%，且用「同奇偶位置不相邻」的数学构造保证符号永不连排**（`separatedPositions`，可证不死循环；两份重复实现合并成 `src/lib/passwordGen.ts` 唯一核心）；② 正则库**30 条里 16 条实测零命中** —— 根因是「整串校验（`^…$`）配了多行样本」的语义错配，改为**候选清单 + `m` 标志**，并在界面上让每条**自报命中数**（`HitBadge`：N 处 / 示例不匹配 / 正则无效），把「哪条是坏的」从不可见变可见；③ 桌面整理**判定为「能力有、入口错」**（Rust `organizer.rs` 本就是真移动文件，但模块首屏指向只登记引用的格子视图）→ **完善不砍**：新增双页签控制台，首屏改成「归类文件」，并常驻**作用目录**栏自证动的是真实桌面。另把冒烟脚本从 9 个用例扩到 **23 个**（新增 probe 类用例，覆盖全部 19 个有示例条的工具 + 正则自检徽标 + 桌面控制台）。

**V26 做的是「不再等用户报错，主动去找同类的缺口，把工具箱的纯逻辑层用外部标准锁住」**：V25 的三条反馈本质上都是「有一整块面从没被任何脚本覆盖」，于是本轮先把覆盖面盘了一遍 —— 结论是 **`src/modules/toolbox/lib/*`（编码 / URL / JWT / JSON / 哈希五个工具的公共实现，约 60 KB）一条断言都没有**。新增 **6 套回归（831 → 1459 条断言）**，锚点全部来自项目之外（RFC 4648 / RFC 1321 / NIST / jwt.io 公开令牌 / Goessner JSONPath 教程数据 / IEC 单位口径），并用 **Node 自带 `node:crypto` 与产品侧 WebCrypto 交叉验证**哈希与 HMAC。过程中**实测浮出并修掉 6 处真缺陷**，其中最危险的一类是「**不报错、只给错答案**」：URL 解析把 `localhost:5173` 读成「协议 localhost: + 路径 5173」（host/port 双双为空）；字节工具切进制时单位不跟着走，`1.5 TiB` 会算成 `1.5 字节`（差 1024⁴ 倍）；JSON→TS 的接口名复用只看键名，同键不同值类型时**静默**给出与数据打架的类型。另把三条**与实现不符的示例描述**改成真话（V25 用户报的正是这一类），并把冒烟从 23 条扩到 **27 条 / 24 个工具全覆盖**（补的 4 个正是「没有示例条」的那几个）。

**V27 做的是「给工具箱加上第一个带网络能力的工具，并顺手清掉识别层的误报」**：① 用户点名**接口测试工具**（类 Postman）→ 新增 `api-tester`：cURL 导入（DevTools 拷贝即还原）· 方法/URL/头部/体编辑 · **Rust 侧 `http_request` 直发请求绕开 webview 的 CORS**（reqwest + rustls，与 updater 共用依赖树；浏览器预览自动降级 `fetch` 并明示受限）· 状态分档 / 耗时 / 体积 / JSON 美化 / 历史 15 条 / **敏感头不落盘** · 8 条免费接口示例点击填充；② V26 的探针方法论继续扫零覆盖面 → **建议条把 `www.example.com`、`1.2.3`、`file.name.txt` 误判成 JWT**（会弹「解析 JWT 载荷」的错误推荐）、8 字母单词误判成 Base64 —— 14 处误报全清（JWT 按 RFC 7515 要求头部解出 JSON 对象；Base64 要求解码为合法 UTF-8）；③ `jsonLocate` 与 V8 差分 0 分歧，但尾随逗号/缺值的**报错文案误导**改准确且指向真正的元凶；④ 回归 14→**17 套（1778 条）**、冒烟 27→**28 条 / 25 工具**、工具自检 313→**325 PASS**。

**V33 做的是「把桌面格子的模型推倒重来」**：用户一张截图 + 五条意见，其中「**并不是整理收纳，而是复制了一份而已**」直接否定了 V30 建立的「文件引用型」格子 —— 自动收录只登记引用、文件本体留在桌面，于是同一批文件在桌面和格子里各显示一份。V33 把模型换成**真实收纳型**：格子绑定磁盘真目录 `桌面/Handy整理/<格名>/`，拖入即真移动（同名自动改名、绝不覆盖、跨卷退化复制+删源），**默认不自动收纳**，`.lnk` 与文件夹原地不动。同时把「闪一下没了/又出来了」的两个根因挖出来：① 心跳自愈判据被 WebView2 的**定时器节流**伪造（90s 无心跳被误判白屏 → 周期性销毁重建），改为「**显示后从未收到任何心跳**」+ 冷却 + 次数上限；② 管理页 `overlayVisible` 是本地 state、从不与真实窗口对齐（且 `addBox`/`autoArrange` 会顺手弹窗），改为以 `grid-overlay-status` 为唯一事实源 + 2s 轮询。并新增**挂件体系**（便签 / 日历·计划，日历直接读工作台同一张 `todos` 表）。自查中还抓掉一个真缺陷：便签「卸载时落一次」的 effect 把 `draft` 写进依赖 → **每敲一个字都落一次库**且顺手取消防抖定时器。**同批补上数据库迁移回归测试**（`cargo test --lib db::migrations` 3 条，迁移此前零断言覆盖）。

**V34 做的是「把桌面格子的三处错误当场纠正，并让挂件真正对齐工作台」**：用户 4 张截图 12 条反馈。
其中最关键的一条 ——「**格子跑到我其他窗口上面了**」＋「**点别的地方他就隐藏消失了**」—— 查明是
**同一根因**：`show_overlay` 里 `apply_attach` 与 `show()` **顺序写反**（`show()` 会把窗口提拔到 Z 序顶层，
把刚贴好的桌面层级顶掉）。修法是调换顺序，并补 `RESURRECT` 冷却重建（格子层「该在就在」，不再一次意外就
永久消失）+ `REASSERT_TICKS` 收紧到约 2.4 秒（错位 5 秒内必纠正）。另修：「两个我的电脑」（取消系统格 +
迁移 v7）、图标样式不一致（改取 48×48 系统图像列表 + `.lnk` 叠层）、「文件夹整理根本不生效」
（`auto_arrange` 里文件夹被整类跳过）、「便签怎么是纯文本框」（改用所见即所得 Markdown 内核）。
布局按用户建议改成**靠右自动流**，挂件（便签/日历）各限一个且日历与工作台**逐项对齐**（农历/节气/休班/
干支 + 点某天加计划 + 悬停看当天全部计划，读写同一张 `todos` 表）。视觉上空格子不再占桌面，格子容器改为
无边框的半透明柔光卡 ——「桌面是大容器，格子是大容器里的小容器」。

**当前卡点：唯一剩下的是「用户装机做 GUI 验收」**（沙箱/当前会话无法验证窗口/托盘/透明/桌面挂载/拖放等真实 GUI 行为 —— 本轮实测连**旧版**程序在 agent 会话里也起不来，见 §1.19.2）。

#### 1.8.1 工作台「挤在一起」的真实根因：min-h 与网格单元格打架

不是配色也不是间距，而是**四层 `min-h-*` 同时大于可用高度**：

| 层 | 原值 | 后果 |
| --- | --- | --- |
| 网格行 | `grid min-h-[440px] flex-1` | 行最小 440px |
| 日历面板 | `h-full` + 内部 **330px** 内容 | 撑满 440px 单元格还要往下溢 |
| 计划面板 | `min-h-[320px]` | 参与抢高度 |
| 便签面板 | `min-h-[420px]`，却在 `h-[260px]` 的壳里 | **必然溢出 160px** |

网格项默认 `min-height:auto` 不会收缩，于是日历那一行的内容**向下溢出**自己的单元格，而后渲染的便签面板把它**盖住** —— 看起来就是「挤在一起 / 内容叠了」。

修法（**保持视觉不变，只改结构**）：

1. 主内容列自身变成滚动容器（`flex min-h-0 flex-1 flex-col overflow-y-auto`）——**宁可有滚动条，也不让面板互相压盖**；
2. 日历行 `min-h-[440px]` 保留（等高要求来自 V21 的 7b），便签行改固定 `h-[300px] shrink-0`；
3. 三个面板的 `min-h-*` 全部换成 `min-h-0`，各自 `overflow-hidden` 或 `overflow-y-auto`，内部按需滚动。

> 教训：**`min-h-*` 和 `h-full` 混用在网格里，等于允许子元素比父格子更高**。要「等高」就必须让父行有明确高度、子项 `min-h-0`，再把滚动条交给最内层。

#### 1.9.2 Quartz 语法：是什么、谁在用、该不该留

**它是什么。** Quartz 是 Java 生态里的任务调度库，它的 cron 表达式是 **6 / 7 段** `秒 分 时 日 月 周 [年]`，比标准的 5 段多了「秒」，另外还有四样标准 cron 没有的东西：`?`（不指定）、`L`（当月最后一天）、`15W`（离 15 号最近的工作日）、`1#2`（当月第 2 个周一）。

**谁在用（这是「常不常用」的答案）。**

| | 标准 5 段 | Quartz 6 / 7 段 |
| --- | --- | --- |
| 长相 | `分 时 日 月 周` | `秒 分 时 日 月 周 [年]` |
| 谁在用 | Linux `crontab -e`、`/etc/cron.d`、cronie、BusyBox crond、**Kubernetes CronJob 的 `schedule`** | Quartz Scheduler、Spring `@Scheduled(cron=…)`、**XXL-JOB**、ElasticJob |
| 最小粒度 | 1 分钟（**没有「秒」这一格**） | 1 秒 |
| 扩展符号 | 无 | `?` / `L` / `15W` / `1#2` |

**结论：保留，不删。** 依据三条：

1. **它不是冷门语法。** 国内 Java 技术栈里 XXL-JOB 是分布式任务调度最常见的选型之一，Spring 的 `@Scheduled(cron=…)` 也是 6 段 —— 砍掉等于放弃这批用户；
2. **真正的「误解」不来自 Quartz 存在，而来自工具没标清哪套写法喂给谁。** 把 `0 0/5 * * * ?` 贴进 `crontab -e`，cron **不会报错**，它只是不跑 —— 这种静默失效才是坑；
3. 反过来，**只要标清平台，两套写法并存对用户是净收益**（同一个工具既能算「服务器上的备份任务」，也能算「Java 应用里的对账任务」）。

**所以这一版做了四件事（全部落成代码 + 回归）：**

| 措施 | 落点 |
| --- | --- |
| 标题降级：工具名改为「Cron 表达式解析」，描述以「标准 5 段（crontab / K8s）」打头，不再把 Quartz 当并列卖点 | `commands/index.ts` 注册项 |
| 输入框正下方**常驻平台提示条**：一句话说清「当前这套写法喂给谁」+ 可展开的两栏对照（谁在用 / 最小粒度 / 扩展符号） | `CronDescriptor.tsx` |
| **误用自动报警**：检测到 6/7 段、或 5 段里混进 `L` / `W` / `#` / `?`，提示条变警示色并把坑直接写出来（「只接受 5 段，多一段会直接报错、任务不生效」） | `cron.ts::platformOf()` |
| 生成器里选了「每 N 秒」「每月最后一天」时，面板内额外提示这两条只能给 Java 侧调度器 | `CronDescriptor.tsx` |

**`platformOf()` 的一个关键细节（也是回归重点）：不能粗筛 `/[LW#]/`。** 月份别名 `JUL` 含字母 `L`、星期别名 `WED` 含字母 `W` —— 粗筛会把最普通的 `0 9 * * WED` 误报成「Quartz 专用」。假警报会让用户开始无视提示，比不提示更糟。所以按「逗号切分后的整段」精确匹配 `L` / `5L` / `15W` / `1#2`，这条由 `scripts/regression/test-cron-platform.mjs`（45 条断言）单独守着。

#### 1.9.4 响应式：从「口头要求」变成「可复跑审计」

用户这条要求（「不要我页面放大缩小后页面结构就变成一堆乱套了」）**无法靠读代码满足**，所以建了常驻工具 `scripts/audit/layout-audit.mjs`：起 Vite dev server + 无头浏览器，对 **24 个工具 + 3 个模块页 × 3 档视口（680 / 1024 / 1680）** 实测，量四个指标：

| 指标 | 抓什么 | 为什么需要它 |
| --- | --- | --- |
| `ox` / `mox` | 整页 / 主内容区横向溢出 | 常规「溢出」检测 |
| `clipX` / `clipY` | **内容溢出但容器不滚** —— 看得见的内容其实够不着 | 溢出被 `overflow:hidden` 兜住时，`ox` 一点不变 |
| `overlap` | 非祖孙关系的块级容器矩形相交 | **「挤在一起」的真正形态**：面板 A 溢出自己的单元格被面板 B 盖住，`ox` 依然是 0 |
| 截图 | 存 `_shots/audit/` | 数字说不清的要靠眼睛 |

**它抓到的两处真缺陷（`ox` 全程为 0，只测溢出会误判成「一切正常」）：**

1. **日历被裁掉近两周**：`CalendarPanel` 的 42 格网格挂 `flex-1`（`flex-basis: 0%`），窄窗口下浏览器把它压进「剩余高度」，680px 宽时日历只显示到 **20 号**，后两周被裁；
2. **「计划」面板被压成 19px 空壳**：上排网格 `flex-1` 在窄窗口下让 flex 子项**先被压缩**而不是溢出 —— 外层内容列虽然写了 `overflow-y-auto`，滚动条根本没机会出现，`min-h-0` 的计划面板被挤成一条缝。

**统一修法**：`lg`（1024px）以下的单栏布局里，**一切 `flex-1` / `min-h-*` 都只保留给 `lg` 起**，各面板按内容高度排布、滚动统一交给外层内容列。即
`grid grid-cols-1 gap-4 lg:min-h-[440px] lg:flex-1 lg:grid-cols-[minmax(0,380px)_minmax(0,1fr)]`、
日历网格 `grid grid-cols-7 gap-1 lg:flex-1`、计划面板 `min-h-[260px] lg:min-h-0`。
复跑结果：**30 个页面 × 3 档视口，溢出 0 / 裁切 0 / 重叠 0**。

> 教训（与 §1.8.1 是同一件事的另一面）：**`flex-1` 在「auto 高度的父容器」里不是「撑满」，而是「可被压缩到 0」**。要撑满就必须给父级明确高度；给不了明确高度时，宁可让内容自然排布 + 外层滚动。

#### 1.11.1 密码生成器：符号不连排是「构造」出来的，不是「修补」出来的
- 起手先**合并重复实现**：组件内联那份与 `@/lib/passwordGen` 各写了一套近似逻辑（V24 遗留），
  只改一处等于只治好一半 → 删掉组件内联实现（−5576 字符），`passwordGen.ts` 成为唯一事实源。
- 默认符号占比 **100% → 25%**（`DEFAULT_MAX_SYMBOL_RATIO = 0.25`，界面新增「符号不连续」开关，默认开）。
- 「不要连着出现多个特殊字符」若用「生成后扫一遍、发现连排就换位置」实现，会引入**死循环与取值偏置**。
  改用**同奇偶位置互不相邻**这一性质**:把可用槽位按奇偶分成两组，只从其中一组抽样 → 抽出的位置两两必不相邻**
  （`separatedPositions`，可证、无循环、无偏置）。
- 容量上限 `separatedCapacity(n) = Math.ceil(n / 2)`：40 位想塞 20 个符号是**做不到的**（首尾被字母占掉后
  只剩 38 个候选位，同奇偶最多 19 个）→ **收敛到容量上限，并把原因写进 `notes` 告诉用户**，绝不悄悄少给。
- 回归 `test-password.mjs` **86 条**：符号两两不相邻 · 符号数精确等于目标（期望值用**独立公式**
  `expectedSymbols = min(max(1, floor(len·ratio)), separatedCapacity(len−2))` 表述，而不是复述实现）·
  首尾必为字母 · 四类齐全 · 约束冲突写 notes 不抛错 · 同种子可复现。确定性随机源用 `mulberry32`。

#### 1.11.2 正则库：30 条里 16 条零命中 —— 用户「不知道是哪个错」正是产品缺陷
- 实测统计：**16/30 条点下去零命中**。根因**不是正则写错，而是语义错配**：
  一批条目是「整串校验」型（`^…$` 锚点），却配了一段**多行样本文本** —— 整串锚点配多行文本永远不可能命中。
  另有几条是数据本身配错：重复词检测（中文没有 `\b` 词边界，须配 `gim` + 专用样本）、剥离 HTML 标签配错文本、
  Docker 容器 ID 与「IP:端口」两条**根本没有自带文本**（点下去无输入可测）。
- 真正的产品缺陷是**「无法分辨哪里错」**：界面上一片空白，用户只能怀疑自己的正则。
  所以修法不是逐条打补丁，而是换一套结构：
  1. 整串校验类一律改配**候选清单**（每行一个值，**故意混入非法值**）+ 显式 `m` 标志
     → 一眼看出「哪几行通过、哪几行被拒绝」；
  2. `RegexExample` 新增 `sampleKind: 'text' | 'list'` **显式标注样本语义**
     （`list` 类型**本该**既有命中也拒绝，回归据此断言）；
  3. 界面每条渲染 `HitBadge`：`N 处`（emerald）/ `示例不匹配`（amber）/ `正则无效`（红）
     —— 把「哪条是坏的」从不可见变可见；匹配空态也改成引导文案（「匹配不上往往是示例不合适」+ 一键连示例填入）。
- 回归 `test-regex-library.mjs` **30 条**：① 每条可编译 ② **每条在自己的示例里至少 1 处命中**（堵零命中复发）
  ③ 断言用例的 expect 全对 ④ `list` 类必须**既有命中也拒绝**（否则等于没区分）⑤ 带锚点却未开 `m` 的必须有自带文本。
  锚点判据用 `pattern.startsWith('^') || pattern.endsWith('$')` —— 直接用 `/[\^$]/` 会把 `\$(?=\d)` 里
  转义的 `$` 误判成锚点。

#### 1.11.4 自测从 9 个用例扩到 23 个（并修掉冒烟脚本自身三个坑）
- 覆盖面：**19 个有示例条的工具全数覆盖**（此前只有 8 个）+ **2 个 probe 用例**（正则自检徽标、桌面整理控制台）。
- 新增 **probe 用例机制**：不点 chip，直接在页面里跑探针函数并断言结构化结果 ——
  适用于「没有示例条、但界面本身就是验收对象」的地方。探针用 **`String(fn)` 原样注入**
  （手写进外层模板串会被当成模板串自己的转义：`\s` 静默退化成 `s`，探针悄悄变形并报假失败）。
- 断言的是**用户能看到的后果**，不是内部状态，例如：
  - 密码「16 位通用」→ 实测生成 16 位、**符号 4 个（≤25%）、连排 = false**；
  - 去重工具 → 页面必须出现「去除 N 行重复」且 **N > 0**（只填进去不算，真去掉了才算）；
  - json-to-ts → 必须真的生成出 `interface Xxx` 与 `ip: string`。
- **反例（V25 自查抓到）**：`relative-time` 原本断言 `body.includes('天前')` —— 而示例 chip 的标签就叫
  「3 天前」，它本身就在 `innerText` 里，**断言恒真、测了个寂寞**。改成在浏览器里**从当前时间重算期望天数**，
  再要求页面出现那个数字（示例用的是固定日期串，天数会随日子漂移，写死「3」第二天就假失败）。
  **自查方法：把自己写的断言逐条问一遍「有没有可能它必然成立」。**
- 修掉脚本自身三个坑（都曾产生假信号或假卡死）：
  1. **`wait --load load` 每页固定空烧 25 秒**（`open` 之后 load 事件早已触发，它只能等自己的超时）→
     22 个页面 = 9 分钟纯等待；改为**页面内轮询就绪**（等 chip 出现 / 等按钮渲染），每页 1~2 秒。
  2. **`spawnSync` 调浏览器 CLI 会在冷启动时卡死**：首次 `open` 会顺带拉起无头浏览器（60~90 秒），
     它是 CLI 的子进程且继承了 stdout 管道 → `spawnSync` 要等到管道关闭（= 等浏览器退出），**timeout 也救不了**；
     改为 `spawn` + `exit` 事件 + 自计时，到点 `SIGKILL` 后照常 resolve。
  3. **`input[type="text"]` 匹配不到没写 `type` 的 `<input>`**（属性选择器只匹配显式写了属性的元素）→
     text-lab 报过一次完全虚假的「示例没填进去」；改为 `textarea, input`。
- 终值：**23 / 23 通过**。

### 1.19 V33 批次（模型推倒重来：格子 = 真实收纳目录 + 挂件容器）

**用户反馈（附截图）**：①「并不是整理收纳，而是复制了一份而已」②「快捷方式应该保留在默认位置」
③「收纳框也是不稳定，莫名其妙又出来了……或者就出现闪一下就没有了，完全没有在控制范围内」
④「可以增加一些有用组件，日历计划任务等……除了工具箱，其他功能都可以融合到桌面整理大师里面，
工作台挂件（日历+计划）便签挂件等」⑤「总之我需要一个强大全面的工具软件」。

**根因（三条，全部是设计层面的，不是小 bug）**：

| 现象 | 真根因 |
| --- | --- |
| 「复制了一份」 | V30 引入的 `grid_desktop_sync` **自动收录**：桌面文件被登记成**引用**后，文件本体仍在桌面根 → 桌面与格子里各显示一份。用户看到的就是「复制」 |
| 「闪一下没了 / 又出来了」 | V32 的心跳自愈判据是「可见 + 90s 无心跳 → 销毁重建」。但 WebView2 对**贴在桌面层的窗口会节流定时器**，心跳间隔被拉长过 90s → 误判白屏 → 周期性销毁重建 = 用户看到的闪一下没了又出来 |
| 「莫名其妙又出来了」 | 管理页 `overlayVisible` 是**本地 state**，从不与真实窗口对齐；且 `addBox` / `autoArrange` 会顺手把挂件层弹出来 → 状态与事实脱节 |

**① 模型推倒重来：文件引用型 → 真实收纳型（`grid.rs` 重写，DB 迁移 v6）**

- 每个收纳格绑定**磁盘真实目录** `桌面/Handy整理/<格子名>/`（与「归类文件」同一根，用户只需认一个目录）；
  格名 → 目录名的清洗在 Rust 侧（非法字符换 `_`、去尾部句点、空名回落「未命名」、截 60 字符防 MAX_PATH）。
- **拖文件进格子 = 真 `fs::rename` 移动**；同名冲突**自动改名 `name (2).ext`，绝不覆盖**；
  跨卷时退化成「复制 + 删源」，两步任一失败都上抛中文错误（宁可不搬，不产生半截状态）。
- 格子右上角 **× = 把文件移回桌面根**（不是删除）。跨格拖拽 = `fs::rename` 到目标格目录。
- **默认不自动收纳**：`grid_desktop_sync` 降级成**纯对账**（按磁盘目录补齐/清理 `grid_items` 登记行，
  一个文件都不动）。只有用户主动点「一键收纳桌面」（带二次确认）或手动拖入才会移动文件。
- **一键收纳只动普通文件**：`.lnk` 快捷方式与文件夹原地不动（用户第 ② 条要求），
  并在报告里明确计入「跳过 N 项」，让用户看到不是漏了。
- `grid_items` 从「真相」降级为**登记缓存**（只为前端提供稳定 id）；磁盘目录是唯一事实源，
  每次列举都 `reconcile_box` 对齐（含用户在资源管理器里手工放进格子的文件）。
- 旧库升级：v6 `ALTER TABLE grid_boxes ADD COLUMN kind/content`，并把历史「系统」格子标成
  `kind='system'`（否则按新模型对账会把「此电脑 / 回收站」这两个 CLSID 虚拟条目当失效条目清掉）。
  历史 `Handy收纳` 目录若存在则继续沿用，不凭空多建空目录。

**② 稳定性：把「假白屏」判据换成真判据**

- 心跳自愈判据从「可见 + 90s 无心跳」改成「**显示后从未收到任何心跳**（冷启动 45s）+ 冷却 300s
  + 最多重建 3 次」。节流导致的「心跳变慢」不再被误判成白屏 → **周期性重建消失**。
- 挂件窗 Z 序校验去抖：`REASSERT_TICKS` 33 → **250**（约 15s），且要求**连续 2 次**不匹配才
  `SetWindowPos` —— 第三方桌面工具（腾讯桌面整理）造成的瞬时抢层不再引发闪烁。
- 新增 `grid-overlay-status` 命令作为**唯一事实源**（`visible/exists/attachMode/iconsHidden`）；
  管理页 2s 轮询对齐状态（解决「莫名其妙又出来了」），并**取消 `addBox`/`autoArrange` 的顺手弹窗**。
- 新增 `grid-debug.log`（`%LOCALAPPDATA%/Handy/`）落盘关键决策，下次现场可取证。

**③ 挂件容器：格子不再只是文件框（`kind` 分四类）**

- `folder` 收纳格 / `note` 便签 / `calendar` 日历·计划 / `system`（此电脑·回收站）。
- **便签挂件**：暖色便签纸，输入即存（600ms 防抖 + 失焦 + 卸载三重兜底）。自查时抓到并修掉一个真缺陷：
  卸载落库的 effect 把 `draft` 写进依赖 → **每敲一个字都落一次库**，还顺手把防抖定时器取消掉
  （导致「打完停手」那一笔反而要等失焦才落盘）。改为「镜像 ref」写法，effect 依赖保持稳定。
- **日历·计划挂件**：月视图（有计划的日期打点）+ 今日计划清单，可直接勾选 / 回车快速新增；
  数据直接读**工作台的 `todos` 表**（同一份数据，桌面勾完工作台同步，不需要新表）。
- 挂件区不参与收纳对账（`reconcile_box` 对非 `folder` 类型直接返回登记行）。

**④ 文案全面去旧模型**（V25–V32 到处写着「只登记引用 / 绝不移动文件」，与新模型直接矛盾）：
`GridManagerView` 头注释与说明卡、`GridOverlay` 头注释、`desktop-organizer/index.ts` 模块描述与关键词、
`OrganizerView`、`DesktopOrganizerConsole` 页签 hint、`sample-smoke.mjs` 的桌面控制台探针断言 —— 一并改写。

#### 1.20.1 ① 格子跑到其他窗口上面 + 点别处就消失 —— **同一个根因：Z 序被 `show()` 顶掉**

两条反馈看似矛盾（一条说「盖在我窗口上面」，一条说「点别处就没了」），实际是**一条链**：

| 现象 | 真根因 |
| --- | --- |
| 「格子跑到我其他窗口上面」 | `show_overlay` 里顺序写反了：先 `apply_attach` 把窗口按基准层插到「桌面正上方」，**再** `show()` —— 而 `show()` 会把窗口提拔到 **Z 序顶层**，刚贴好的层级立刻被顶掉 |
| 「点别的地方他就隐藏消失」 | 同上。格子层此刻在顶层却**不是激活窗口**（`make_unfocusable` 不抢焦点），用户点任意别的窗口 → 那个窗口被激活、盖到最前，格子层就被压在下面，看起来「消失了」 |

**修法（两处 `show_overlay` 分支都要改）**：`show()` 在前，`apply_attach()` 在后 —— 先让它显示，
再把它按基准层插回「桌面正上方」。同时 `reassert_attach` 的日志里补上 `overlay / host / below` 三个
HWND，下次现场只凭一行日志就能区分「attach 压根没生效」还是「被别的窗口插队」。

#### 1.20.2 ② 驻留：格子层「没了就没了」→ 该在就重建

用户原话是「除非 handy 主程序退出，他才跟着退出」—— 即格子层属于**长期驻留**，不该被任何一次意外
销毁永久带走。旧的轮询线程碰到「窗口不在了」一律 `break` 退出线程，等于一次意外之后就再也不管了。

- 轮询线程现在**区分两种「窗口不在」**：用户主动收起（`overlay_visible = 0`）→ 正常退出；
  状态仍是「显示中」→ **自动重建挂件层**，带 [`RESURRECT_COOLDOWN_SECS`] = 30 秒冷却
  （防止销毁-重建风暴），并落 `grid_log` 取证。
- 判定降到**约 30 秒一次**（`missing_ticks % 500`，轮询周期 60ms），避免每 60ms 查一次库。
- `REASSERT_TICKS` 由 V33 的 250（约 15 秒）**收紧到 40（约 2.4 秒）**：仍保留「连续两次判定才动手」
  的去抖（两次之间隔着整整一个轮询周期，足以滤掉第三方桌面工具造成的瞬时抢层），但真正的错位
  现在 5 秒内必被纠正 —— 直接回应「某些情况才能永久驻留」。

#### 1.20.3 ③ 靠右自动流布局（`arrange_position`）

从**右边缘**开始摆（对齐桌面图标的阅读习惯），摆满一列往左推一列，一行到底换下一行。

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `ARRANGE_MARGIN` | 32 | 距工作区边缘留白 |
| `ARRANGE_STEP_X / Y` | 344 / 268 | 列/行步距（盒宽 320 × 高 244 + 间距） |
| `ARRANGE_BOX_W / H` | 320 / 244 | 新建格子的默认尺寸 |
| `ARRANGE_MAX_COLUMNS` | 8 | 超宽屏也别一路排到左边缘之外 |

`col = 0` 最靠右，`x = (work_width - MARGIN - BOX_W - col * STEP_X).max(MARGIN)` 兜住极窄工作区。
`layout_work_width()` 取挂件窗实际 `inner_size / scale_factor`（拿不到则退主显示器工作区、再退 1280），
新建格子（`grid_box_upsert`）与一键收纳都走同一套落点。

#### 1.20.4 ④ 便签改 Markdown 实时渲染 · 日历挂件对齐工作台

- **便签**：原来是个裸 `<textarea>`，现在直接用项目里已有的所见即所得编辑器 `RichMarkdown`
  （`contentEditable`，**敲完即渲染**，无工具栏、无编辑/预览切换 —— 与工作台便签同一套内核）。
  外层补 `.note-markdown .md-preview` 主题覆盖：暗色主题下正文/引用/代码块原先是白底白字
  （RichMarkdown 继承主题 `--foreground`），已改成暖色系深字 + 浅色代码块底。
- **日历**：完全对齐 `workstation/CalendarPanel`，复用同一批纯函数（`src/lib/lunar.ts`、
  `src/lib/holidays.ts`、`planUtils.buildMonthGrid`、`isSameDay`），所以**农历 / 节气 / 节日 / 休班角标 /

  - **点某天 = 选中该天** → 下方清单切到那天，新增计划直接落在这一天的 09:00；
  - **悬停 tooltip** 列出那天**全部**计划（`✓` 已完成 / `·` 未完成），不再只画一个圆点。

#### 1.20.5 ⑤ 「两个我的电脑」与图标样式不一致

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 收纳后桌面**有两个「我的电脑」** | 「此电脑 / 回收站」是 Explorer 的**常量条目**（CLSID 虚拟项），桌面本身一定画一份；格子里的 `kind='system'` 盒子又画一份 | 用户明确「系统这个不需要」⇒ **取消系统格**：删掉 `ensure_system_box`（不再自动建），并追加迁移 **v7** 清掉历史系统格及其登记行 |
| 格子里的图标**样式都变了** | 图标是 `SHGetFileInfoW(SHGFI_LARGEICON)` 取的 **32×32**，桌面「中等图标」是 **48×48**；且没带 `.lnk` 箭头叠层 | 改走系统图像列表 `SHGetImageList(SHIL_EXTRALARGE)` 取 **48×48**，并统一加 `SHGFI_LINKOVERLAY | SHGFI_ADDOVERLAYS` → **快捷方式箭头与桌面一致**；取不到才退 32×32。前端 `FileIcon` 不再写死 32px，按图标实际尺寸渲染并加投影 |

> windows-rs 0.58 签名坑（已写进代码注释）：`IImageList` 在 `Win32::UI::Controls` **需要额外开启
> `Win32_UI_Controls` feature**；`SHGetImageList` 被包成**泛型返回** `Result<T>`（一个参数，不再手写 IID）；
> `IImageList::GetIcon(i, flags) -> Result<HICON>` 是**返回值式**签名（老版本是 `&mut HICON` 出参），
> `flags` 要裸 `u32`，故 `ILD_TRANSPARENT.0`。

#### 1.20.6 ⑥ 收纳模型收口：系统格取消 · 文件夹纳入 · 只留快捷方式不动

- **文件夹的整理根本不生效** —— 根因：`auto_arrange_inner` 里 `if item.is_dir { continue }`，
  文件夹被整类跳过，于是「文件夹」格子永远是空的。现在**只有 `.lnk` 跳过**，文件夹纳入「文件夹」格；
  跨卷移动的兜底分支同步补上目录递归复制（`copy_dir_recursive`），不再只处理文件。
- 用户在**资源管理器里手工放进格子目录**的文件现在也会被 `reconcile_box` 收录（磁盘目录是唯一事实源）。
- `AutoArrangeReport` 新增 `foldersMoved`，toast 文案据此分别报「文件 N / 文件夹 M / 跳过 K」，
  让用户看到**为什么**有些东西没动，而不是以为漏了。

#### 1.20.7 ⑦ 空格子不占桌面 · 挂件唯一 · 视觉融入桌面

- **只展示「有东西的格子」**：`visibleBoxes` 过滤掉 `kind='folder'` 且 `items.length === 0` 的格子 ——
  空框浮在壁纸上只挡视线。但空格子**没有消失**：解锁布局（编辑态）后全部显形，可往里拖文件 / 重命名 /
  删除；平时在管理页照旧可管。有内容就自动出现在桌面上。挂件（便签/日历）与内容无关，任何模式都展示。
- **便签 / 日历各限一个**：`addWidget` 改成**幂等** —— 已存在同类挂件时不再新建，工具栏对应按钮直接置灰
  （而不是点了才弹提示）。前端（`GridOverlay`）与管理页（`GridManagerView`）双处都改。
- **视觉融入桌面**：格子容器改 `rounded-2xl` + `bg-white/[0.045]` + `backdrop-blur-[3px]` + 柔和阴影，
  正常模式**没有边框**（像画在壁纸上）；只在解锁编辑态才出现虚线天蓝描边做「可拖拽」提示。
  图标网格 `minmax(84px, 1fr)` 配 48px 图标。**桌面 = 大容器，格子 = 大容器里的小容器**。
- 重命名格子标题的能力**此前已有**（双击标题），本轮只是补进管理页说明。

## 3. 开发约束速查（违反会返工）

1. **所有 Rust 命令必须 `async fn`** —— 历史上同步命令在主线程执行会楔死 WebView2 的 COM STA，导致全部 IPC 永久 pending。
2. 前端**禁止组件内直接 `invoke`**，一律经 `src/lib/ipc.ts` 封装；SQL 只在 `src/core/data/*Service.ts` 里拼。
3. **DB 迁移只追加、幂等**；schema 三方一致（migration SQL = Rust 结构体 serde camelCase = `src/types/*.ts`）。
4. 模块注册：`src/modules/<id>/index.ts` 导出 `ModuleMeta`（`import.meta.glob` 自动发现）；命令注册在 `src/modules/toolbox/commands/index.ts`，`id` 全局唯一 kebab-case。
5. **新图标必须登记 `src/lib/icons.ts`**，否则静默回退成扳手图标。
6. 同一文件多处编辑**必须串行**（并行 Edit 会丢改动）。
7. 禁止对真实用户目录写操作；测试用 TEMP 沙箱。
8. 系统动作类功能**只增白名单表**（`src-tauri/src/commands/sys.rs` 的 `table()`），前端永远只传 `actionId`。
9. **打开非 PE 目标（`.cpl`/`.msc`/目录/协议）只能走 `ShellExecuteW`**，不要用 `std::process::Command`（会得到 os error 193）。
10. **窗口显隐/置顶以设置项为单一事实源**：`settings.barPinned`/`mainPinned` 由主窗口 `useAppStore.subscribe` 驱动 Rust；订阅**必须限定 `windowRoot === 'main'`**（贴条窗也跑 `main.tsx`，不判断会自己叫自己）。
11. **改 `RichMarkdown` 前必读组件头部注释**（记录了大量 contentEditable 内核坑），并按 §4 的逐字符冒烟回归。
12. **代码高亮规则只有一份**：词法表在 `src/components/CodeBlock.tsx` 的 `LANGS`，通过 `tokenizeCode` / `highlightCodeHtml` 同时供只读组件与便签编辑器使用 —— **加语言只改这一处**，不要在别处复制正则。
13. **桌面挂载不要再回到 `SetParent` / `HWND_BOTTOM`**：现行方案是「顶层窗 + `SetWindowPos(hwnd, host, …)` 插在桌面宿主之上 + `WS_EX_NOACTIVATE`」。`SetParent` 会丢透明且触发重建（闪 + Explorer 重启后失效），`HWND_BOTTOM` 会掉到壁纸下面。
14. **新增设置项 = 三处**：`src/core/types.ts` 的接口 + `src/core/settings.ts` 的 `DEFAULT_SETTINGS`（`withDefaults` 靠它给旧 `settings.json` 补默认值）+ 需要跨窗口生效时在 `main.tsx` 的**主窗口限定**订阅里驱动 Rust。
15. **纯逻辑模块（`src/lib/*.ts` 里不碰 React/DOM/Tauri 的）必须进回归**：`scripts/regression/run.mjs` 用 Node ≥ 22.18 的**原生类型剥离**直接 `import` 源码 `.ts`（**不要为测试引入打包步骤**）。加新套件 = 写 `test-<name>.mjs`（import 源码 + 打印 `PASS/FAIL` + 用 exit code 报结果）并把文件名加进 `run.mjs` 的 `SUITES`。改动 `cron.ts` / `lunar.ts` / `holidays.ts` / `sql.ts` / **`textlab.ts`** 后**打包前必跑**。V22 起 `test-sql.mjs` 还兼守「**示例库自洽性**」—— 所有面向用户的教学示例（`sqlSamples.ts`）都必须无语法错误、可格式化、能识别出语法点。**面向用户当教材用的常量数据，也要有人守。** V23 起套件扩到 **6 套 / 715 条断言**（cron 114 · cron-platform 45 · lunar 32 · holidays 30 · sql 357 · textlab 137）。其中 `test-cron-platform.mjs` 额外守一条**反向用例**：`JUL`（含 L）/ `WED`（含 W）/ `SAT` 这类**月份与星期别名不得被误报成 Quartz 专用** —— 假警报会让人开始无视提示，比不提示更糟。
16. **删除文件的额度是「按回合累计」，不是「按命令」（V22 发现，V23 修正结论）**：本机 node 有安全垫片，**单个回合内累计删除 > 50 个即拒**。关键点是**额度跨命令累计**——同一回合里先跑 `clean-dist.mjs` 用光额度，随后的 `vite build` 会被**连带拦下**，表现为 `CLEAN_EXIT=1` + `VITE_EXIT=1` 一起出现，极易误判成「前端编不过」。所以：
    - **首选**：在没有任何其它删除动作的回合里直接 `node node_modules/vite/bin/vite.js build` —— vite 的 `emptyDir` 对 `dist/assets` 只发 1 次 `rmSync(recursive)`，远低于阈值。（此路径 **V23 已复验通过**：`vite build` 单独一条命令 → `VITE_EXIT=0`，52 个 dist 文件。）
    - **真要逐文件清**：用 `node scripts/clean-dist.mjs --max=40`（V23 新增参数，单回合上限），**`exit 2` = 还有剩余**，再开一个新回合继续。不要不带参数跑（默认会一路删到被拦）。
17. **响应式布局铁律（V23 血泪）**：
    - **`flex-1` 在「auto 高度的父容器」里不是「撑满」，而是「可被压缩到 0」** —— 窄窗口下它会先把内容压扁，而不是产生滚动条。**要「撑满」必须给父级明确高度**；给不了，就让它按内容自然排布、把滚动交给外层。
    - 因此**一切 `flex-1` / `min-h-*` 都要用 `lg:` 前缀关进宽屏**，窄屏走「单栏 + 内容高度 + 外层滚动」（写法见 §1.9.4）。
    - **改完布局不是靠眼睛看，要跑 `node scripts/audit/layout-audit.mjs`**（见 §4）。只看「有没有横向溢出」会漏掉真缺陷：V23 抓到的两处，**`ox` 全程为 0**，只有 `clipY` / `overlap` 能抓到。
18. **布局审计同样会吃光删除额度（V24 补充约束 16）**：`scripts/audit/layout-audit.mjs` 要开关 28 个页面，
    无头浏览器每页都会删临时文件 —— 实测**跑完审计之后，同一回合里的 `vite build` 必然被垫片拦下**
    （报 `count:57, threshold:50, scope:"turn"`）。两条出路：① **审计与 build 分回合跑**（正解）；
    ② 加 `--emptyOutDir=false` 跳过清空（**构建全程不删文件**，代价是 dist 里会留旧哈希产物、
    安装包体积涨约 0.5 MB —— V24 实测 exe 从 9.33 MB 涨到 9.85 MB，额度恢复后重跑干净构建才回落）。
19. **冒烟/审计脚本的五条硬规矩（V24 建、V25 补齐）**：
    - **必须跑在「新鲜的 dist」上**：`sample-smoke.mjs` 读的是 `dist` 产物。改完前端却没 build，
      它验的仍是**上一批代码** —— V25 差点拿 V24 的 dist 去验 V25 的示例条，那样「找不到 chip」
      会被误读成「功能坏了」。**顺序永远是：改代码 → `tsc` → `vite build` → 冒烟。**
    - **不要用 `agent-browser wait --load load`**：`open` 之后 load 事件早已触发，这条命令等不到那次事件，
      只能等自己的超时 —— **实测每页固定烧 25 秒**（22 个页面 = 9 分钟纯等待，还会被前台超时踢成后台任务，
      看起来像卡死）。改为**在页面里轮询就绪**（等 chip 出现 / 等按钮渲染出来），每页 1~2 秒。
    - **首次 `open` 会冷启动无头浏览器（实测 60~90 秒），必须单独给长超时**：用 60s 的固定超时去调它，
      等于每次都把冷启动**掐断在半路** —— 浏览器留在半活状态，之后每一步都慢到超时，整轮看起来像「卡死」
      （V25 第一次跑冒烟就是这样跑了 9 分钟没完，容易误判成脚本写错）。两个脚本现在都显式处理：
      `sample-smoke` 给首次 open **180s** + `eval` 失败重试一次；`layout-audit` 开局先做一次
      **`WARMUP_TIMEOUT = 180s` 的预热 open**，之后每页只要 ~0.3 秒。
    - **超时路径要「一定」能返回**：`sample-smoke` 的 `ab()` 用 `spawn` + `exit` 事件 + 自计时，
      而不是 `spawnSync`（子进程拉起浏览器后管道被继承，`spawnSync` 何时返回取决于管道关闭时机，不够确定）。
    - **页面内探针函数必须用 `String(fn)` 注入**，不要手写进外层模板串：模板串会把 `\s` / `\n`
      当成**自己的转义**处理（`\s` 静默退化成 `s`），生成的探针悄悄变形并报出完全虚假的失败信号。
    - **冒烟脚本要逐条立即落盘**：V25 第一次跑卡了 9 分钟，而日志是 0 字节（全部跑完才写文件）——
      完全看不出卡在哪个用例。改成「每条一行、写一行落一次盘」，脚本自己就能指出卡点。

## 6. 续接开工三件事

1. **先跑五绿确认树健康**：`cargo check`（经 `scripts/rust-env.sh`）+ `tsc --noEmit` + `node scripts/regression/run.mjs`（**6/6 套 / 715 条断言**）+ `node scripts/audit/tool-audit.mjs`（**0 FAIL / 0 WARN**）+ `node scripts/audit/layout-audit.mjs`（**0 溢出 / 0 裁切 / 0 重叠**），均应为 exit 0。`vite build` 见 §3 约束 16 / 18（**别先跑 `clean-dist.mjs`；也别和布局审计同回合**）。
2. **确认上一轮验收结论**：若用户已装机验收，把发现的问题按「现象 + 期望」记录到本文档 §2 或当日日志，再派人修。
3. **选下一个方向**：默认优先级 = ① 修验收问题 → ② §2.2 技术债（其中「**文本处理台 Phase 2**」是价值最高的待办；其次是「清空工具草稿」的界面入口，`usePersistedState` 已导出 `clearPersisted` 但没接界面）→ ③ §2.3 Phase 2 模块。
